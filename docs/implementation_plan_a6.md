# TUI worktree provenance gate

## Checklist

- [ ] Before entering the TUI or dispatching any operation, verify which Git working trees are being used. Run this gate for every entry point and mode, including `NO_STD_IN=True`, help, and collect-only; do not start application/container/UI processes, acquire credentials, call an LLM, or run tests before it completes.
  - [ ] Resolve canonical base api-agent and selected resource-pack/test-owner repository roots from the launcher context, rather than the current working directory. Check both repositories independently when the selected pack belongs to another repository; de-duplicate a demo pack or pack nested in the same Git working tree.
  - [ ] Require an available Git CLI and verify each selected root belongs to the expected working tree. Missing Git, an invalid selected checkout, or failure to enumerate/inspect required worktrees must stop with a nonzero exit status and actionable diagnostics.
- [ ] Enumerate all registered worktrees for each relevant repository using Git's machine-readable, safely delimited output and invoke Git with argument arrays. Handle paths containing spaces and special characters without shell evaluation. Do not scan unrelated repositories or ignored files/caches for modification dates.
  - [ ] Identify each root, branch or detached HEAD, checked-out commit SHA, and checked-out HEAD's commit datetime. Use the commit's committer timestamp consistently, with an explicitly labeled timezone in the displayed date.
  - [ ] Find the newest filesystem modification time among nonignored paths with unstaged changes and nonignored untracked files. A staged-only change does not count; a path with both staged and unstaged changes does. Check candidate paths against ignore rules even when tracked, so an ignored file cannot make a checkout newest. Use safely delimited Git path lists and inspect only reported candidate paths.
  - [ ] Rank a worktree by the newer of its checked-out HEAD commit timestamp and its newest eligible dirty-file timestamp. Show which source determined the result. Include all tied newest worktrees; a selected root tied for newest is current enough and does not require stale-worktree acceptance.
  - [ ] Report unstaged deletions and rename source paths without inventing a deletion timestamp; an absent path contributes no file mtime. Inspect an existing rename destination when Git reports it as an eligible dirty path. State explicitly that ordering reflects observable commit/file timestamps, not a recoverable date for deleted files.
  - [ ] Report locked, inaccessible, missing, or prunable registered worktrees accurately. Do not prune, repair, switch branches, or modify them automatically. An inaccessible/missing runnable checkout prevents confirming the comparison and exits nonzero; distinguish administrative bare entries without a runnable working tree rather than assigning them a fabricated recency timestamp.
- [ ] If the selected checkout is not among the newest worktrees for either relevant repository, present a pre-TUI warning with every relevant root's branch/HEAD, timestamp and determining reason, which roots are being run, and which are newest. Require explicit stdin acceptance before continuing.
  - [ ] This is an intentional exception to `NO_STD_IN`: even an otherwise unattended invocation must stop for this acknowledgement when its checkout is stale. There is no flag/environment variable to bypass or pre-authorize the warning. Only an explicit affirmative stdin response permits continuation; decline, silence, EOF, or unavailable stdin exits nonzero instead of running against an unacknowledged older checkout.
  - [ ] When the selected roots are newest, continue without asking or reading stdin. Preserve ordinary help/collect-only shortcuts and mode-specific stdin rules after this gate. Keep the worktree warning distinct from E2E human acceptance and integration/E2E Continue; acknowledgement does not authorize any test execution.
- [ ] Add deterministic requirements-focused tests with simulated Git/filesystem/stdin behavior: missing Git, invalid roots, base-only and external-pack-plus-base launches, unrelated current directories, newer commits versus newer dirty files, ignored files, staged-only changes, mixed staged/unstaged changes, untracked files, deletions/renames, ties, detached HEAD, path spaces/special characters, and inaccessible/prunable entries.
  - [ ] Verify the full comparison is checked for both repositories, including only one being stale; confirm selected/latest markers and timestamp reasons are accurate.
  - [ ] Verify affirmative acknowledgement versus decline/EOF/unavailable stdin, including stale `NO_STD_IN`, help, and collect-only invocations. Current roots must not read stdin; blocked roots must not acquire credentials, start processes, or execute/collect tests before acknowledgement. Verify flags/environment variables cannot silently accept.
