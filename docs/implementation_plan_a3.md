# Playwright E2E evidence and retained-browser debugging

## Checklist

- [ ] Run every E2E test through Playwright against the actual UI, including the initial "Ok" test. API-only behavior checks belong in integration tests, not as substitutes for UI E2E execution. Preserve the interactive test picker, explicit Continue, and E2E human-acceptance requirements; headless browser operation does not mean unattended TUI execution.
- [ ] Capture both `response_text` and `response_html` when present, including responses containing both, and attach their original values and rendered evidence to Allure under the test/attempt identity. Capture relevant conversation rounds, not only the final response, so clarification and approval flows can be reviewed.
  - [ ] Before taking rendered-response screenshots, use the agent modal's maximize control and scroll the conversation/response content to the top. Account for independently scrollable HTML frames/containers. Wait for rendering/layout to settle before capture; the initial image must not start at the bottom and cut off the answer.
  - [ ] Capture complete text and HTML output, using full-page/element capture or additional scroll-region captures where appropriate. Verify the top and remaining content are represented; a page screenshot alone must not silently omit content inside a scrollable modal/frame. Keep separate attachments for text and HTML when both exist. Capture available failure-state evidence too.
- [ ] For any Playwright error, invoke the [shared all-tab error capture](implementation_plan_a4.md) before response capture or cleanup. Screenshot each tab's current whole viewport even if no response exists; error evidence preserves current state rather than applying the normal maximize/scroll-to-top preparation.
- [ ] Declare validated `E2E_BROWSER_RESOLUTION` as a `WIDTHxHEIGHT` string, default `1440x900`, with positive integer dimensions. Apply it to the Playwright viewport in both normal and debug runs and record it with artifacts. Make it configurable through the normal `.env`/environment/CLI precedence.
- [ ] Run browsers headlessly by default. Declare boolean `E2E_DEBUG` (default `False`) with normal config/ENV/CLI support, but metadata must explicitly exclude this field from the startup missing-default/save-default prompt step. An unset value silently stays False; it must not itself trigger default-configuration interaction. Keep it visible in help and the configuration cleanup mode.
  - [ ] On the E2E test-selection screen, show an additional `d` Debug start action only when a non-empty strict subset of available E2E tests is selected. Positional selectors may pre-filter this subset, or the user may choose it interactively. Determine whether it is a subset against the entire discovered suite, not merely the filtered picker list, and do not enable debug for selectors that match every test.
  - [ ] Pressing `d` starts the selected tests with effective `E2E_DEBUG=True` for that invocation, after the same explicit continuation/human acceptance as normal E2E start. If debug is explicitly configured, validate the subset restriction before execution; never silently start an all-tests debug run. Normal selected tests can still run headlessly when debug is off.
  - [ ] Debug always uses headed browsers and retains a separate browser for each selected test after it finishes, passed or failed, so the user can inspect its rendered state at the end. Keep browser/Playwright ownership alive beyond pytest test teardown and report completion; don't accidentally close the browser with its fixture or driver. Confirmation attempts retain attempt identity/evidence without opening an unbounded browser per attempt.
  - [ ] Keep normal Allure, usage, quota, and retry reporting in debug runs. Allow the user to close retained browsers/end the debug session explicitly; the TUI stays responsive and manages owned browser processes without auto-closing them merely when a test completes.
- [ ] Add deterministic coverage for resolution validation, silent debug default, strict-subset gating (including pre-filtered selectors), headed/headless selection, and browser retention/cleanup orchestration. Verify maximize/top-first and text-only/HTML-only/combined artifact capture using a controlled UI fixture before relying on live LLM E2E evidence. Live E2E checks still require user acceptance.

Implementation references: [Playwright screenshots](https://playwright.dev/python/docs/screenshots) describes page and element capture; [Playwright browsers](https://playwright.dev/python/docs/browsers) covers browser installation and headed/headless support. Ensure the installed browser supports both normal headless and debug headed operation.
