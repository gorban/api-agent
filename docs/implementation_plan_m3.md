# Provider contract hardening before real consumers

The version-1 exports and synthetic owners exist, but their consumer contract is provisional. Complete the following before parallel concrete adapters or operation consumers depend on it. Keep upstream protocols outside core; use independently authored synthetic fixtures for public proofs.

## Ordered checklist

- [ ] Complete operation activation and selected dependency preparation; the implemented `activation_kinds` matrix already separates runtime factories/routes from configured selections. Declaration discovery may support help/configuration, but import, dependency preparation, client startup, route activation and UI launch happen only for capabilities needed by that operation. Prove unusable unrelated selections do not block units, help, collection, LLM-only rendering, access-only checks, UI-free integration or local-run without UI. Allow separately owned callback listeners without launching a frontend.
- [x] Specify the minimum shared LLM data: messages/content, tools and calls/results, generation options, structured-output requests, available selections, completion outcomes, stream event kinds and terminal usage. Declare optional features and consistently reject unsupported requests. Keep API invocation payloads adapter-defined. Verify one unchanged renderer with two synthetic LLM adapters before freezing these schemas.
- [x] Define immutable operation context with correlation, one overall deadline spanning authentication/retries/streaming, cancellation semantics and separate bounded cleanup. Specify safe operational error kinds, execution disposition (`not_started`, `possibly_executed`, `completed`), optional retry delay and retry authority. Preserve approved safe errors; sanitize unknown failures and prohibit automatic mutation replay when execution is uncertain. At an expired deadline only a fresh native coroutine proves `not_started`; opaque or suspended awaitables are `possibly_executed`. Hidden preexisting delegates of opaque inputs remain their external owner's disposal responsibility.
- [x] Replace bare stream lifetime assumptions with a managed stream lease. Hold ownership through iteration, exhaustion or explicit awaited close. Cover early break, cancellation, iteration failure, partial output and exactly-once terminal usage; never rely on garbage collection to stop a stream. Coalesce child cancellation at read/close boundaries so awaited disposal is not interrupted by a second cancel; retain cleanup-pending ownership until retry confirms disposal.
- [ ] Propagate typed cleanup disposition through session, provider, runtime and operation owners. Keep a failed child's required clients/modules/browsers/prerequisite leases until confirmed disposal, retain a retry handle, and allow independent siblings to close. Test pending cleanup across every parent boundary. Share coalescing, cancellation shielding and retry policy without erasing distinct owner responsibilities.
- [ ] Complete live-operation credential scoping/revocation and IPC; in-process readers and helpers already support username, password and TOTP through [the helper tasks](implementation_plan_a2.md). Bind each retrieval to the allowed role/account and live operation; reject unsupported kinds and late replies after revocation.
- [ ] Specify debug run-complete versus inspection-open states, worker/driver survival, cleanup acknowledgement/retry and unexpected worker exit. Version credential IPC with operation/worker/attempt, allowed role/account, deadline and revocation; do not transfer browser objects or opaque token getters between processes.
  - [ ] Reuse the shared `wait_browser_result` browser-closure guard for pending provider browser waits across integration/E2E/local-run and for the separate E2E UI browser when wiring its runner. The caller owns cancellation/draining of underlying work. Closing before completion must finalize an unsuccessful outcome promptly, release owned listeners/tasks and publish available failure evidence; accepted authentication callbacks remain successful. Verify normal and debug retention paths, unrelated-tab closure and browser disconnection. A closed browser must not leave a test RUNNING until its operation timeout.
- [ ] Define supported bundled/external distribution and declaration resolution, including complete relocated pack manifests, schemas and required dependencies. Source-tree file factories remain supported; narrow wheel-export checks do not prove an installed pack works.
- [ ] Document declaration authority: who owns each field and whether contributions may change defaults, validators, requiredness or applicability. Preserve approved explicit override precedence and reject incompatible or unauthorized weakening. Do not silently change existing field semantics while settling this contract.
- [x] Separate non-inference access adapters from the selected inference provider. Specify independent selection, scoped authentication/routes, optional discovery/usage capabilities and no inference capability. API principal validation must not require an unrelated LLM service identity.
- [ ] Join consumer-level conformance for activation, two LLM adapters, pending parent cleanup, early stream close, safe errors/deadlines, worker inspection and credential isolation. Human-review the concrete contract before declaring its supported surface stable. Prior foundation coverage does not establish these new proofs.

## Before planner/API consumers

- [ ] Add an optional provider-owned tool/catalog seam: generic names, descriptions, input schemas and result/evidence metadata. Keep API-specific query/schema types inside the API provider. Prove one unchanged consumer can discover and invoke a synthetic REST tool without API-type branches. This requires no production REST provider or demo backend, and does not block the initial renderer-only milestone.

## Early phase boundary

The [included personal GPT adapter](implementation_plan_f2.md) is early work. Real demo UI/Nx apps, demo GraphQL servers and demo non-GraphQL providers are later work. Public units use synthetic fixtures; early live API/UI acceptance may use separately owned external pack providers. Those private consumers do not become public dependencies or fixtures.

## Current implementation checkpoint

Shared inference data, safe operational classifications/context, managed stream leases and independently selected access adapters are implemented. Units use two distinct synthetic transport mappings through the same consumer. Username helpers and strict in-process kind/index binding are implemented. Runtime/operation cleanup and explicit capability activation are covered by synthetic parent-ownership proofs. Human review of this concrete chunk remains pending.

This does not complete selected-provider dependency manifests, relocated installed packs, declaration authority, worker IPC/debug survival, live-operation credential revocation, concrete adapters or runner/browser integration. Base/pack dependency installation still uses their project manifests; provider-specific preparation must adopt the activation matrix when those manifests are implemented. Keep the larger activation/distribution/credential checklist entries open until then.

## Selected configuration and credential follow-through

- [ ] Add browser-free scoped credential acquisition for API-key providers before the included GPT consumer. Derive active credential role labels from selected provider declarations, including mode predicates; do not hardcode an intermediary LLM User. Retrieve the selected entry password only, register it with the emission boundary, own its in-memory lifetime, reject late/revoked replies, and allocate no browser for that acquisition. No separate plaintext API-key setting is needed for the included GPT adapter.
- [ ] Reverify bundled provider defaults relative to base root/package, explicit pack overrides and installed relocation once the bundled factory exists. Help/configuration discovery must not execute its factory.
