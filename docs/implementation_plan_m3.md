# Provider contract hardening before real consumers

The version-1 exports and synthetic owners exist, but their consumer contract is provisional. Complete the following before parallel concrete adapters or operation consumers depend on it. Keep upstream protocols outside core; use independently authored synthetic fixtures for public proofs.

## Ordered checklist

- [ ] Define an operation activation matrix separate from configured selections. Declaration discovery may support help/configuration, but import, dependency preparation, client startup, route activation and UI launch happen only for capabilities needed by that operation. Prove unusable unrelated selections do not block units, help, collection, LLM-only rendering, access-only checks, UI-free integration or local-run without UI. Allow separately owned callback listeners without launching a frontend.
- [ ] Specify the minimum shared LLM data: messages/content, tools and calls/results, generation options, structured-output requests, available selections, completion outcomes, stream event kinds and terminal usage. Declare optional features and consistently reject unsupported requests. Keep API invocation payloads adapter-defined. Verify one unchanged renderer with two synthetic LLM adapters before freezing these schemas.
- [ ] Define immutable operation context with correlation, one overall deadline spanning authentication/retries/streaming, cancellation semantics and separate bounded cleanup. Specify safe operational error kinds, execution disposition (`not_started`, `possibly_executed`, `completed`), optional retry delay and retry authority. Preserve approved safe errors; sanitize unknown failures and prohibit automatic mutation replay when execution is uncertain.
- [ ] Replace bare stream lifetime assumptions with a managed stream lease. Hold ownership through iteration, exhaustion or explicit awaited close. Cover early break, cancellation, iteration failure, partial output and exactly-once terminal usage; never rely on garbage collection to stop a stream.
- [ ] Propagate typed cleanup disposition through session, provider, runtime and operation owners. Keep a failed child's required clients/modules/browsers/prerequisite leases until confirmed disposal, retain a retry handle, and allow independent siblings to close. Test pending cleanup across every parent boundary. Share coalescing, cancellation shielding and retry policy without erasing distinct owner responsibilities.
- [ ] Complete credential kinds with username, password and TOTP through [the helper tasks](implementation_plan_a2.md). Bind each retrieval to the allowed role/account and live operation; reject unsupported kinds and late replies after revocation.
- [ ] Specify debug run-complete versus inspection-open states, worker/driver survival, cleanup acknowledgement/retry and unexpected worker exit. Version credential IPC with operation/worker/attempt, allowed role/account, deadline and revocation; do not transfer browser objects or opaque token getters between processes.
- [ ] Define supported bundled/external distribution and declaration resolution, including complete relocated pack manifests, schemas and required dependencies. Source-tree file factories remain supported; narrow wheel-export checks do not prove an installed pack works.
- [ ] Document declaration authority: who owns each field and whether contributions may change defaults, validators, requiredness or applicability. Preserve approved explicit override precedence and reject incompatible or unauthorized weakening. Do not silently change existing field semantics while settling this contract.
- [ ] Separate non-inference access adapters from the selected inference provider. Specify independent selection, scoped authentication/routes, optional discovery/usage capabilities and no inference capability. API principal validation must not require an unrelated LLM service identity.
- [ ] Join consumer-level conformance for activation, two LLM adapters, pending parent cleanup, early stream close, safe errors/deadlines, worker inspection and credential isolation. Human-review the concrete contract before declaring its supported surface stable. Prior foundation coverage does not establish these new proofs.

## Before planner/API consumers

- [ ] Add an optional provider-owned tool/catalog seam: generic names, descriptions, input schemas and result/evidence metadata. Keep API-specific query/schema types inside the API provider. Prove one unchanged consumer can discover and invoke a synthetic REST tool without API-type branches. This requires no production REST provider or demo backend, and does not block the initial renderer-only milestone.

## Early phase boundary

The [included personal GPT adapter](implementation_plan_f2.md) is early work. Real demo UI/Nx apps, demo GraphQL servers and demo non-GraphQL providers are later work. Public units use synthetic fixtures; early live API/UI acceptance may use separately owned external pack providers. Those private consumers do not become public dependencies or fixtures.
