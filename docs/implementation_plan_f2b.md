## Configuration and discovery

GPT configuration is at [its executable declaration](../src/api_agent/llm_providers/gpt/cfg/config.toml). GPT_STATE_DIR is a hidden advanced override; empty uses the protected per-user location. There is no GPT_PROFILE setting. Attended setup may reuse a unique cached connection or identify the user through OAuth when the cache is empty/ambiguous. Unattended setup requires the LLM User account descriptor and shared password manager/CLI; its retrieved username binds reuse to that account. Missing account/manager is a named setup prerequisite before authentication or cache selection. A missing matching connection starts the observed initial email step; duplicate matches still require attended sign-in. Username retrieval failures carry sanitized typed interaction errors: fall back to a fresh attended OAuth flow only when interaction is allowed, without reusing an unbound cached account. Password/TOTP/consent automation remains pending.

Factory creation, help, collection and test selection do not authenticate. Integration tests explicitly request setup when needed. Recorded execution requires interactive Start (or the explicit integration DEBUG exception) and Allure storage configuration; collection-only does not start setup or storage. E2E execution and its mandatory human acceptance remain separate work.
