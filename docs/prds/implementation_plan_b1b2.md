# Workflow declaration v2 grammar

[Contract freeze](implementation_plan_b1b1.md) · [Conversion](implementation_plan_b1b.md)

The executable v2 source is inert UTF-8 Markdown whose filename ends in `.md.html`. Raw HTML, script tags, unknown headings and executable expressions are rejected within executable content. The separately versioned, exact presentation envelope and generated nonexecuting diagram/navigation section specified in [B1a](implementation_plan_b1a.md) are the only presentation exceptions; arbitrary markup remains unsupported. After extracting that envelope, a root starts with exactly `# Workflow v2`, has a `## Graph ID` one-column table with one stable ID, and a `## Flow` ordered list of linked direct steps. Every step has a four-column marker, a `component` or `node` label, a stable ID, and a link to one nested `.md.html` declaration. Each component declaration has its own `## Flow` of direct children. This recursively establishes execution order and ownership once, without repeating descendants at root or duplicating routes in another table.

Each nested document starts `# Component v2: id` or `# Node v2: id`, matching its linked step. Root and children may contain grouped fixed-column `Components`, `Functions`, `Bindings`, `Edges`, `Prompts` and `Timeouts` tables with the v1 meanings. Rows are combined in document and flow order, then validated as one graph. A node additionally has exactly one `## Native` table with `Registry`, `Kind` and `Source` columns. Kind is `llm` or `deterministic` and must match the registered callable role. The source link identifies an existing Python file in a declared root; it is not another workflow declaration. A component cannot have a Native table. Conditions and native functions remain registered Python callables; the documents contain identifiers, never evaluated code.

Prompts use ordered `Prompts` rows with a local file link or an `@id` reference. An inline prompt is `## Prompt: id` followed by one fenced `text` block. Its bytes are part of the admitted resource snapshot. JSON input and output links must contain valid local object schemas using JSON Schema draft 2020-12. Configuration source links preserve the numeric timeout declaration contract. All links resolve relative to their declaring document or through the explicit pack root token, then must remain within a declared root after symlink resolution. Directory discovery never selects a graph or replacement.

`load_definition(entry, *, base_root, pack_root, replacements=(), entry_root=None)` admits one graph. Callers can explicitly identify a nested entry as `base` or `pack`; otherwise the loader infers its owning root. Its immutable result holds `graph_id`, `definition_id`, `entry`, declared `roots`, ordered `replacements`, complete captured `resources`, frozen contents and an execution `layout` projection. Each resource records kind, logical path, content bytes and SHA-256. Definition identity hashes the grammar version, graph ID, declared logical resource paths and hashes, and ordered replacements; absolute installation paths and caller working directory do not affect it. Inline prompts have a distinct logical namespace and cannot alias filesystem paths. `Replacement(target_id, entry, root_id)` explicitly replaces one known declaration by stable ID and declared-root-relative entry. Unknown targets, duplicate targets, undeclared roots and unsafe links fail before effects. Format v2 limits nesting to 64 component levels and total steps to 4096 with located diagnostics.

Resolve a stable-ID replacement before reading its original declaration. Validate the original link syntax, declared-root containment and step kind, but capture only the selected replacement subtree. Editing or deleting the unselected original must leave the selected definition and its ID unchanged. The explicit native catalog loader must verify all selected native source bytes against the admitted snapshot before executing any top-level catalog code; stale or unavailable source fails before effects.
The replacement path and selected declaration target must both end in `.md.html`; other file extensions fail before the graph is admitted.

Resource admission uses bounded regular-file reads through declared-root-relative descriptors without following symlinks. It limits each real resource to 8 MiB and the unique captured snapshot to 64 MiB. A second bounded read rejects changed or unavailable resources before returning the definition; nonregular files and path races produce located declaration errors.

Execution uses `Workflow(definition, registry, ...)` so prompts, schemas and configuration come from admitted bytes. `load_native_catalog(definition, source)` is an explicit opt-in for a trusted selected catalog; it compiles the admitted bytes with the declared filename and never rereads a changed file. Each v2 callable must originate from this loader for the exact admitted definition and selected source. A source change or stale callable requires a new definition and native restart. The legacy `load_layout` remains only for focused compatibility units. The managed browser viewer, production immutable profile, richer typed state/reducer grammar and execution overlay remain separate dependent work; unsupported executable v2 constructs must fail rather than be ignored.
