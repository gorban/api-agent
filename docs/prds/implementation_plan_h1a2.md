# Local-run navigation and catalog review repairs

[Core operation](implementation_plan_h1a1.md) · [Startup tabs](implementation_plan_k2.md)

- [ ] Replace Browser destinations and Log sources typed-number text menus with shared-style, focusable buttons. Enter activates the focused choice, including the initially selected first choice; mouse activation works too. First ten choices have immediate hotkeys 1 through 9 then 0. Remaining choices use focus navigation without concatenated numeric input.
- [ ] Support arrows and standard Vim directions: h left, j down, k up, l right. Preserve focus/selection across live status and log refreshes. Closing a menu returns to the same running operation. Menu navigation keys must not accidentally open another menu, and displayed read-only logs must not present an editable menu cursor.
- [ ] Render destination name and URL on separate button lines with wrapping and useful focus styling. Ctrl+C explicitly copies the focused destination URL; on log-source buttons it copies the source name. Reuse the existing safe clipboard implementation and feedback. Navigation/refresh alone never writes to the clipboard; copy failures preserve the menu and operation.
- [ ] Start and foreground the enabled prepared UI last in the original managed browser. Core order is home, actual selected flow, UI; without UI, flow is last. Reserve the following tracing order as home, enabled tracing viewer, actual flow, enabled UI. Preserve exact owned-tab checks, replacement-page readiness, graph identity and cleanup receipts.
- [ ] Make catalog loading visible and bounded by the supported backend operation budget rather than a shorter first-page-only timeout. A slow initial provider setup must populate the real model/version/reasoning choices without reloading the page or fabricating choices. An actual failure must remain actionable and permit explicit retry without restarting the local operation or duplicating authentication.
- [ ] Prove focused-button activation, tenth/later choices, Vim/arrows, wrapping, refresh stability, explicit copy and failure handling through actual Textual events. Prove tab order/foreground with original and replacement UI pages. Reproduce delayed catalog setup and genuine errors with controlled HTTP/browser checks, including retry and request cancellation. Preserve privacy and no eager inference.
- [ ] Complete meaningful causal controls, exact applicable coverage, source/installed artifacts, independent lane reviews, public-boundary checks and external joined review. Do not use live inference merely to test startup/catalog behavior.
- [ ] Human review of menus, clipboard, reordered tabs and working Studio catalog/chat. Earlier accepted scopes retain their approvals; these reported findings remain open until fixed and reviewed.
