# Pluggable password-manager implementations

## Checklist

- [x] Define a common password-manager interface for retrieving username, password and TOTP independently. API-key authentication requests only the password; subscription login requests the fields needed by its current page. Consumers depend on this interface rather than manager-specific functions.
- [x] Supply 1Password and Keeper implementations in separate files within api-agent. Preserve the established CLI commands, CSV/raw parsing, closed stdin, actionable errors, owned process cleanup, shared timing and secret-safe diagnostics.
- [x] Declare a stable manager identifier, friendly picker label, implementation file/factory location and conditional CLI executable default for each implementation. Selected resource packs can contribute additional implementations. Resolve declaration paths relative to their owning declaration; users select enum identifiers/labels rather than Python paths.
- [x] Merge base and selected-pack declarations into the available enum choices, validation and conditional executable defaults. Preserve `1password` and `keeper` identifiers, the blank initial choice, existing descriptor storage and explicit executable overrides. Configuration discovery, help and wizard rendering must not execute credential helpers or authenticate.
- [x] On **Edit shared password manager**, place a read-only **Password manager implementation path** field between **Password manager** and **CLI executable path**. Display the selected implementation's actual resolved `.py` path and update it immediately when the dropdown changes, including pack-contributed implementations. With no manager selected, show `-`. Keep it outside the editable fields and Tab order; do not persist this derived path in the credential descriptor.
- [x] Validate malformed declarations, conflicting identifiers, missing implementation locations and incompatible interfaces before credential retrieval. When a pack is changed or removed, refresh available choices and give an actionable error for a stored manager that is no longer available; do not silently substitute another manager or delete saved configuration.
- [x] Use the same retrieval contract for API keys, subscription login and other provider/pack consumers. Keep account roles and paired indexes independent of manager implementation selection; do not add an API-key-specific user role.
- [x] Add conformance tests for both bundled implementations and a synthetic third implementation contributed by a resource pack. Verify friendly enum choices, the read-only implementation path's position and immediate dropdown updates, real dispatch through the unchanged consumer interface, independent field retrieval, executable defaults/overrides and inactive-pack removal. Invalid registrations must fail without invoking a helper.
- [x] Preserve correction/reset of saved managers from inactive packs, retaining role arrays and explicit CLI drafts without silently substituting a manager. Validate cold and mounted canonical/legacy recovery, environment/CLI precedence and malformed/conflicting descriptors.
- [x] Capture the selected pack registry in operation owners and worker snapshots independently of the operation owner directory; keep registry choices isolated across concurrent operations.
- [x] Reject retargeted implementations, asynchronous/generator hooks and nonregular files before credential execution. Read POSIX directory components without following replacements; keep unverified non-POSIX race hardening as a later portability task.

- [x] Complete the combined unit/coverage gate and independent adversarial review before committing: 3,390/3,390 applicable units pass at 100% lines and branches in every measured file.
