# Shortcut presentation and test-selection search

- [x] Present active previous/next account actions as `[ / ] Loop through users`, highlighting only brackets. Preserve separate click/key actions, disabled gates and existing user-index wrapping. Reuse the shared footer wherever those actions are available.
- [x] Serialize initial shortcut-footer composition and binding-driven recomposition. Discard queued composition for inactive or pruning screens so rapid startup/results transitions cannot mount duplicate tab hints. Preserve the first-position Tab hint and keyboard focus behavior.
- [x] Enter regex filtering from the unit/integration/E2E picker with `/` (first matching row) or `?` (last matching row). Replace ordinary footer hints with a one-line editable query and right-aligned `Esc exit`. Every valid edit resets the row cursor in that direction. Invalid regexes retain the last valid projection and display an error; use case-sensitive regex search with ordinary inline flags supported.
- [x] Search full displayed tag/category, file and test names. Matching a tag/file includes its tests. Preserve the original row order; omit All tests. Filter without changing checked membership or future-test scopes. Count unique checked nonmatches in one checked `<N> other tests` row. Unchecking it removes only those nonmatches, removes the row, and selects the last surviving match above it. Toggle overlapping highlighted rows as one union, preserving file/tag recollection intent.
- [x] When a valid search leaves no rows and no checked tests, show the same `Select at least one test before continuing` message as Start selected tests, without adding a placeholder row. Clear it when a changed query finds a match, even if no tests are checked. Preserve invalid-regex error precedence.
- [x] While search is open, `s` starts the selected tests only when the Start selected tests button has focus. With focus in the table or query field, it inserts `s` into the search term.
- [x] From table focus during search, route Left/Right and Shift/Ctrl selection or word variants to the query's native editing actions. Preserve table membership, row cursor, vertical navigation and the established Tab cycle.
- [x] Keep vertical arrows and j/k, their shifted range variants and page/edge range keys acting on the table while editing. Preserve conventional j-down/k-up. Left/right and their text-selection variants edit the query; h/l are literal characters. Tab cycles test list → Start selected tests → search field when visible → test list; Shift+Tab reverses the order. Enter toggles highlighted table rows; Space inserts query text when editing or toggles rows when table-focused. Printable non-navigation characters typed with table focus resume query editing.
- [x] Give selected query text precedence for Ctrl+C on every platform, including macOS. Clear its text highlight after successful copy, then copy full highlighted row names separated by newlines when no query text is highlighted. Preserve native paste and selection replacement. Support platform cut on selected text without advertising a shortcut; never delete edits made while an asynchronous clipboard write was pending. Reuse the existing clipboard helper.
- [x] Escape restores ordinary rows/hints and focuses the same test/file/category by identity, scrolling it into view; otherwise use the nearest surviving row. Preserve checkbox changes, clear stale ranges on row rebuilds and leave normal operation startup/recollection/human acceptance unchanged.
- [ ] Reuse the grouped user presentation in future local-run and E2E account controls when those consumers are implemented. Do not introduce separate footer or search logic for individual test modes.
