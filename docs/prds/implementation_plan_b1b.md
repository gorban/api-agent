# Workflow format conversion and equivalence

[Resource format](implementation_plan_b1a.md) · [Existing runtime and fixture](implementation_plan_b2.md) · [Browser tabs](implementation_plan_k2.md) · [Staged checks](implementation_plan_i1.md)

This converts the existing generic runtime and independently authored example, preserving their behavior. It does not replace the application's existing integration/human-acceptance gate or resume deferred research. External packs own their declarations, prompts and native callables; public examples must not be derived from private graphs.

## 1. Freeze contracts and conversion coverage

- [ ] Version the `.md.html` grammar and typed intermediate representation, retaining root `flow.md.html`, nested declarations, registry bindings, ordered prompt sections, state/types/reducers, conditions, retries, scoped deadlines and streaming. Keep conceptual diagram metadata nonexecuting. Reject unknown/ambiguous or unsupported executable constructs before effects; do not silently omit them or evaluate expressions from Markdown.
- [ ] Inventory all existing generic parser/compiler entrypoints, CLI actions, selected-flow/pack consumers, resource loaders, diagram projections and packaged fixture inputs. Map each old behavior and resource to a new declaration/binding and a deterministic equivalence assertion. Preserve old accepted evidence; explicitly disposition obsolete paths only after the replacement passes. Do not duplicate a graph's routing or prompt order in a second hand-maintained representation.
- [ ] Define explicit graph selection and stable-ID replacement contracts. Select one graph or one explicitly composed graph; omitted replacements retain base behavior. Preserve declaration/pack roots and precedence. Configuration-field overrides do not imply graph merging; directory collisions and incidental discovery order never choose workflow overrides.

## 2. Parser, compiler and packaged example

- [ ] Convert `layout.py`, `execution.py`, workflow CLI, `contrived.py`, `fixture_driver.py` and every discovered consumer together. Resolve nested declaration, prompt, schema, configuration and callable links through verified allowed roots, independently of cwd. Validate broken/ambiguous links, duplicate IDs, missing replacements, traversal/symlink escapes and incompatible binding types before executing a node.
- [ ] Migrate the permanent independently authored fixture and its manifests to an explicitly selectable `flow.md.html` entry with nested resources; retain native Python callables. Package root/nested declarations, prompts, contracts, SVGs and viewer licenses. Root application viewing must identify the graph actually selected, not substitute the qualification fixture for it.
- [ ] Update resource lookup, installed CLI commands, independently authored public examples/grammar documentation and complete source/dependency fingerprints. A semantic fixture change or fingerprint change requires fresh reviewed qualification under its existing gates; never change hashes merely to retain a sampling cap. Do not authorize inference or spending by performing a format migration.
- [ ] Test old/new transitions and outputs with deterministic providers/tools: branch/join/loop behavior, ordered prompts, state/reducers, clarification and approval/resumption, retry/error/cancellation paths, streaming/tool outputs and timeout boundaries. Use the shared nested timeout/progress interface; preserve remaining-parent budgets and existing retry clocks. Exercise applicable legacy contracts rather than weakening tests to accept missing behavior.
- [ ] Verify wheel installation and an extracted deployment artifact from unrelated directories, without sibling source checkouts. Verify selected pack roots, graph/resource navigation, callable import identity and packaged provenance; retain licenses and exact full unit line/branch coverage before code commits.

## 3. Viewer, application and enforcement

- [ ] After format/fixture equivalence, implement `--view-flow` through the shared managed Playwright/server lifecycle. Keep it read-only: no graph invocation, provider login or app startup. Preserve inert help/collection and validate conflicting launch options through the normal CLI/configuration mechanism.
- [ ] After selected external declarations conform and the managed Run local/browser/UI/tracing prerequisites are implemented, reuse that viewer in Run local's final tab. Derive the static declaration/diagram view and displayed resolved overrides from the invocation's compiled definition; show its graph identity/source fingerprint so a stale or unrelated diagram cannot masquerade as the running graph. Preserve tab readiness/order and ownership from K2.
- [ ] Wire declaration-derived temporary PlantUML generation and strict staged-snapshot freshness into the existing managed checks, sharing the same read-only CI entrypoint. Explicit generation writes unstaged files only. Never execute a graph/provider or copy an external pack into public output just to build a diagram.
- [ ] Update each applicable README Get started only with delivered behavior and the `actual LangGraph flow` link. Independently review equivalence, resource isolation, freshness and browser disposal; human-review selected graph/overrides and ready-tab order. Format implementation alone does not claim complete application or E2E acceptance.
