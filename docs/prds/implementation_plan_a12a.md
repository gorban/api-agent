## Measurement and candidate plan

An October 2026 local collection froze 21,716 unit identities and 18 integration identities. Seven unprofiled unit-model samples gave median/max 1.252/1.401 seconds for `groups`, 2.717/2.805 seconds for an individual toggle, 2.776/2.826 seconds for a file toggle, and 7.649/7.862 seconds for an all-suite toggle. The corresponding 18-case medians were below 0.15 milliseconds. These are model timings, not input-to-screen latencies; seven samples are too few to establish a useful p95. One separate profiled `groups` call took 6.234 seconds under profiling, dominated by group-row construction and repeated file membership scans; profiler overhead and a different selection state preclude treating that duration as an unprofiled latency.

An exploratory headless run populated 22,341 rows in 9.93 seconds and recorded several roughly 4.7-second pilot-settled navigation calls. It ended with a memory error under a 1.8 GB virtual-address limit before toggles or review; peak RSS was 1,537,596 KiB. Other probes overlapped and resource pressure confounds these observations. Pilot settlement includes harness scheduling and does not capture a terminal frame. Do not infer event-to-visible-row latency or a complete memory peak from this run.

Textual 8.2.8 renders cropped visible lines, but `DataTable` retains all inserted rows and sizes each new row's cells. The picker inserts all rows, and refresh currently revisits the full selection and table. Cropped rendering alone therefore does not eliminate population, sizing or full-table updates. The approved implementation uses shared virtual scrolling while preserving global selection and scrolling semantics.

The collected unit IDs had median length 119 characters, 95th percentile 169, and maximum 8,388,720; total ID length was 50,135,790 characters. Forty-one IDs over 10,000 characters accounted for 47,422,989 characters, largely from oversized test parameters without explicit readable pytest IDs. A separate 45-second headless profile on that catalog attributed 25.66 cumulative seconds to table line rendering, including 25.21 seconds to Rich character-width checks. Earlier diagnostic runs with incompletely recorded source and configuration suggested a substantial long-label rendering cost; retain them as exploratory, not a controlled baseline. Their 256-character label control preserved model identities and memberships but truncated Ctrl+C cell copy. Search, mouse and complete copy behavior were not measured. The controlled run still took 6.62–6.73 seconds for individual/file/all toggles and 18.93 seconds for all-selected review, then hit the address limit on return.

A subsequent source-bound, sequential headless repeat on the same catalog used a 1.8 GB virtual-address limit and unavailable history. With original labels, entry took 10.443 seconds and four pilot-settled navigation calls after three and six seconds idle took 4.665–4.707 seconds; peak RSS was 1,319,576 KiB. The later 256-character diagnostic took 4.988 seconds to enter and 0.089–0.096 seconds for the same calls, with 247,236 KiB peak RSS. Both runs completed, but order and cache effects remain possible. The diagnostic's copy truncation remains a known defect; these four calls are not a useful p95, ordinary startup measurement or a captured terminal frame.

## Approved implementation and remaining measurements

Long picker labels now use bounded, distinct previews while full selection labels remain available for copy and search. Replacement pickers reconstruct missing full labels from the current selection. Oversized parameter cases use explicit IDs; old exact selectors are not aliased and prior results remain unchanged. Plain navigation avoids clearing table caches when no selection range exists; real range changes and clearing still invalidate them.

On a 21,738-case real catalog, a final-source normal-terminal driver test measured 100 warm up/down movements at each of the top, scrolled middle and end after three, six and thirty seconds idle, respectively. Nearest-rank p95 was 17.49, 17.49 and 17.89 ms; maxima were 24.84, 27.36 and 25.76 ms. Initial entry took 5.51 seconds and peak RSS was 115,876 KiB. A marker followed rendering of the cursor row and terminal output through a pseudo-terminal; this is a display opportunity, not captured physical pixels. Idle and position were paired, the run used an unavailable-history control, and the measurements do not establish every navigation pattern or a general responsiveness guarantee.

In a separate headless control with 18 integration cases selected and history unavailable, the actual Review button opened selected-test configuration in 0.740 seconds and returned in 0.553 seconds. Single headless unit-catalog samples still took 4.67 seconds for search, 3.18 seconds to leave search and 6.47–6.68 seconds for individual, file and all-suite toggles. These remain substantive performance work; a failed isolated-source review attempt and its ownership/configuration limitations are retained rather than counted as success. Independent review, representative repeated action measurements, current configuration and history attribution, full-suite checks and human acceptance remain open.

The bounded warm unit-picker navigation repair was human-approved. Search, toggles, configuration/history profiling and full-suite interactive execution remain separately scoped; navigation acceptance does not close those measurements.

## Warm action follow-through

The [shared virtualized picker](implementation_plan_a12a1.md) now covers unit, integration and E2E selection. Cached memberships and compact selection storage remove repeated catalog scans; visible cells are lazy while identities, search and selection remain global. On 21,845 real cases, final-source headless All-off/search-open samples were 0.243–0.347s/0.274–0.396s; they are not p95 or physical frames. Final PTY navigation p95 remained 17.38–17.51ms. All 21,852 units passed exact coverage. The child records source/installed checks, independent review, attribution, final external gates and separate human acceptance. Broader configuration/history and full-suite interactive-execution profiling remain distinct.
