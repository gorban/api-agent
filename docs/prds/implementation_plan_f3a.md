# Optional native quota-client preparation

The native Codex quota client is an optional measurement source for subscription execution. Quota, pricing, and history reads do not install software or initiate sign-in. At the first execution point that needs a quota observation, the launcher may prepare a native client and use its separate ChatGPT sign-in. Application OAuth and inference remain unchanged; application credentials never enter the native process.

## Requirements and acceptance

- [x] An execution-only accounting preparation hook resolves an existing client or provisions public `@openai/codex@0.160.1` into an owned user cache through npm's official registry. Installation is bounded, ignores lifecycle scripts, checks exact top-level and native platform-package archive integrities plus installed file ownership/content before cached execution, and retains the installed package's license/notices. No global installation or source-tree dependency is required. Help, collection, API-key execution, pricing and history avoid this work.
- [x] With an existing native ChatGPT account, compare its email to the selected verified application connection before reading quota. A different or unrecognized existing account cannot be replaced or used silently.
- [x] If no native account exists, attended execution shows the native client's sign-in URL in the managed browser and watches browser closure while awaiting completion. Completion is checked against the selected account. Unattended execution reports that native sign-in is needed and continues inference without a quota observation; there is no automatic unattended login. Never use the application token to sign in the native client.
- [x] An unavailable client, failed installation, declined/interrupted sign-in, account mismatch, malformed protocol response, or unsupported quota window yields a safe accounting error; successful inference is not blocked. Pure quota reads never initiate installation or sign-in.
- [x] Preserve stable allocation identity, unique observation IDs and one-point quota precision. Do not claim the application and native client share a meter until a separate human-controlled exclusive-use check confirms it.
- [x] Exercise installation, matching, login, timeouts, cancellation, cleanup and execution fallback with synthetic clients and states; independent adversarial review and focused mutations cover account matching, cache containment and execution-only preparation.
- [x] Synthetic native quota-client tests fix the observation clock explicitly and derive reset timestamps from that clock. Verify captured observation time and just-before/exact/after reset boundaries; an expired or current reset remains a rejected response. These controls never execute a real native client.
- [ ] Deferred human acceptance of real optional provisioning and account-match diagnostics; separately establish whether application inference and the native client share the same meter. The user explicitly deferred this review on October 12, 2026; it does not block implemented batch completion or subsequent work, and shared metering remains unverified.

The execution seam is `GPTProvider.aprepare_accounting`, which delegates to `gpt.quota_setup.prepare_quota_client` before the short snapshot deadline. `asnapshot` and `read_quota` only read; neither installs nor signs in. The provider retains an owned browser for attended login and its prepared executable or safe error for the selected account. The quota reader rechecks the native account around each measurement. Existing signed-in mismatches are refused; changing accounts requires a separate explicit native-client action outside this flow. Native children receive a minimal runtime environment and no application secret or inherited npm authentication settings. The installation's local fingerprint detects changed cache files; it is a local integrity check, not a guarantee against a hostile process running as the same OS user.

Automatic native provisioning targets Linux and macOS x64/arm64 hosts, with Node.js 16 or later, npm and access to the public npm registry. Linux uses the standard user cache (or absolute `XDG_CACHE_HOME`); macOS uses `~/Library/Caches`. Platform mapping has controlled tests; live installation on those platforms remains unverified. Missing prerequisites affect optional quota observations; inference continues. The installed package remains in the user's managed cache with its license and notices. Reuse validates exact package and platform archive integrities, a local content fingerprint, executable containment, file ownership and permissions, and the CLI version. Validation is limited to 1,000 files, 256 MiB per file and 512 MiB total, with interruptible hashing outside the event loop. An already installed native Codex CLI can still be used on Windows, but automatic Windows provisioning is unavailable.

- [ ] Add automatic Windows native quota-client provisioning only after its file ACL checks, managed cache, and executable launch have been verified on Windows with controlled and live setup checks.

Cache metadata reads are bounded to 1 MiB for the package lock and 4 KiB for
the sealed marker. File descriptors must identify an owned regular file with
safe permissions and match the pre-open identity. Nonblocking/no-follow opens
reject replacement FIFOs and links; cancellation is checked while hashing and
reading. Invalid cache metadata remains an optional accounting failure.

Public protocol basis: [Codex app-server documentation](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server) and the installed public Codex 0.160.1 app-server schema for `account/read`, `account/login/start`, `account/login/completed`, and `account/rateLimits/read`. [OpenAI's Codex CLI example](https://developers.openai.com/cookbook/examples/codex/build_iterative_repair_loops_with_codex) recommends pinning the CLI version for reproducibility. Protocol and installation availability may change; unsupported responses remain unavailable accounting, never zero usage.
