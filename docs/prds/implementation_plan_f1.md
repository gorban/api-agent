# Shared LLM adapter requirements

The included [personal GPT provider](implementation_plan_f2.md) and replaceable external LLM adapters use the same [generic contracts](implementation_plan_m.md). Complete [consumer hardening](implementation_plan_m3.md) first. Core supplies orchestration and shared LLM shapes; transport/authentication/cache/metadata remain provider-owned. Non-inference access adapters have separate capabilities and do not inherit inference requirements.

## Checklist

- [ ] Implement the versioned factory/capabilities for discovery, completion, streaming and structured output. Preserve the UI-selected model and generation options; return normalized results/errors and supported capability descriptions, with deadlines/cancellation and explicit runtime client disposal.
- [ ] Advertise only supported operations/features. A static-key adapter omits authentication or provides an explicit async no-op, applies its configured secret to each request, and never starts a login browser or asks for an indexed vault account. Browser/cache tasks below apply only to providers advertising those needs.
- [x] Provide the shared api-agent `LLM_CACHE_POLICY` enum: empty (provider defaults), `off`, `medium` (shortest supported retention) and `high` (longest supported retention). Common generation options and worker frames preserve the effective policy. Providers advertise `cache_policy`, validate route/selection support before authentication/inference, and translate only supported policies. Authentication-token and response-result caching are independent.
- [ ] Implement these presets in each additional adapter; an Anthropic-capable adapter should map off to no cache controls/breakpoints, medium to 5m and high to 1h. Verify its actual selected route can honor off; do not claim automatic gateway caching is disabled solely by omitting explicit writes.
- [ ] Contribute typed protocol, authentication and request-metadata settings before first executable use. Receive application/pack identity and tracing context through generic services; build the provider's required headers consistently across discovery, generation, retries and usage reads. Human-review actual settings before any outbound authentication/provider traffic.
- [ ] Register optional attended start/status/completion/recovery handlers through the shared registrar, binding protocol transactions to generic initiating request ownership. Validate provider-specific state/identity/expiry in the adapter; core does not interpret protocol claims or callback names.
- [ ] Implement optional unattended `authenticate` returning the callable, asynchronously disposable `LLMAuthSession` in [the browser contract](../architecture/provider_architecture.md). Use the runtime-owned dedicated headless session and role-bound reader; retrieve fresh challenge credentials on demand. Share refresh/state across authenticated calls without sharing across identities.
- [ ] Own persistent authentication cache policy and storage. Match the selected account, validate file/state format and freshness, avoid credential/token leakage, and refresh valid reusable state when needed. Define private file naming/format/permissions, expiry and corruption behavior in the adapter. Core has no fixed cache filename, token claim or storage format.
- [ ] Serialize/coalesce login/refresh, bound failures, cancel owned background tasks and make disposal idempotent. Getter calls after disposal fail explicitly. Attended access remains usable without descriptors; unattended failure does not falsely report successful login or replay completed actions.
- [ ] Implement optional authenticated usage snapshots without inference, including quota/reset data where supported. Return usage/token counts for completions/streaming/retries without double-counting overlapping cache/reasoning totals; unsupported metrics remain unavailable.
- [ ] Supply optional cost estimation from usage rows and before/after snapshots. Own prices, allocation and quota arithmetic; return finite nonnegative amount/currency or unavailable. Distinguish reset-spanning/unavailable snapshots from measured zero; core must not assume quota points equal currency.
- [ ] Verify provider-owned protocols with controlled pages/transports/cache fixtures and correct-authentication validation mutation checks. Walk real login branches with the user in the provider workspace when needed; core browser utilities own evidence/cancellation, not upstream selectors.
- [ ] Join deterministic contract tests before live authentication-only integration, then authenticated discovery with a zero-inference transport guard. Record Allure/usage/privacy evidence from the first real integration; only after configuration and authentication review proceed to the initial renderer test. Keep every live integration/E2E behind its interactive acceptance rules.
