# Historical workflow source identity

[Inspector](implementation_plan_b1c.md) · [Execution evidence](implementation_plan_b1c1.md) · [Recorded viewer](implementation_plan_b1c2.md)

Bind historical execution overlays to the declaration documents actually consumed by that invocation. A commit reference helps locate source; verified content establishes a match. This work extends the existing source/resource fingerprints and does not replace execution qualification or full runtime provenance.

## Capture and deterministic identity

- [x] At compilation, freeze the selected entry and every Markdown declaration/resource actually consumed, including nested documents and resolved pack overrides. Compute fingerprints from those same captured bytes rather than rereading mutable files during publication or viewing. Preserve selected-root, replacement and resolved-graph identities separately.
- [x] Define a versioned SHA-256 document manifest: logical owner namespace, owner-relative normalized path, byte length and SHA-256 for each consumed document. Sort entries by owner/path with a specified deterministic comparison and canonical serialization before hashing the manifest. Preserve document byte order and contents; sorting must not reorder graph declarations. Reject duplicate/ambiguous normalized paths. Absolute machine paths and repository credentials are not provenance identifiers.
- [x] Store this aggregate hash and per-document entries in the manifest-hashed Allure execution artifact, together with each owning repository's full commit object ID and object format. Verify consumed documents against those commits under the prerequisite below. A pack/provider checkout needs its own provenance; the application repository's SHA alone cannot describe it. Gitless installed resources need verifiable packaged committed-document provenance; unavailable/unverifiable provenance must reject reporting-enabled graph execution with the explicit reporting-skip alternative.
- [x] Bind the captured and executed resolved graph projection to the captured declaration identity. Preserve existing broader execution fingerprints and independently admitted callable source identity; a Markdown-only digest does not establish Python implementation equivalence.
- [ ] Bind generated and historical views to the captured declaration identity and record parser/renderer versions or fingerprints separately when viewing is implemented. Generated HTML is not the declaration source of truth; disclose any unavailable historical implementation verification.

## Uncommitted source policy

- [x] Require committed, verified inputs for the document-hash pathway whenever Allure reporting is enabled. Reject any relevant staged, unstaged, untracked or ignored-untracked document, including staged changes whose working bytes happen to match HEAD. Enumerate the actual consumed inputs; ordinary Git status output must not hide an ignored input. Apply this only to the hash pathway, not unrelated repository edits or Python links outside it. Do not automatically commit, stash, reset or alter the working tree.
- [x] Before graph execution/inference, validate a coherent snapshot of owning commits, index state and consumed working bytes; detect capture races and use the same frozen documents for hashing and execution. Reject a dirty or unverifiable graph with safe affected paths and an actionable message: commit the inputs, or explicitly disable Allure through [SKIP_ALLURE_REPORTING](implementation_plan_d3.md). Do not introduce a separate strictness toggle. Tests that consume no graph documents acquire no unrelated graph-source prerequisite.
- [x] The explicit `--skip-allure-reporting` / `SKIP_ALLURE_REPORTING=True` escape hatch permits uncommitted graph inputs by disabling Allure entirely for that invocation. A warning-only or captured-projection fallback must not permit a new Allure report for those inputs. Preserve in-memory source identity for permitted local inspection; normal privacy limits still apply and a scrubbed projection cannot claim byte-exact source. Existing incomplete historical records remain inspectable with their original limitations.

## Historical lookup and rendering

- [ ] Open a previous test/attempt against its captured projection or declaration source verified at the recorded commits. Resolve objects only in explicitly mapped local repositories/approved artifact stores; read without checking out or modifying the user's working tree. Verify every selected path/blob and the aggregate digest, plus resolved override identity. Never substitute today's flow because the commit, object or content is missing or mismatched.
- [ ] Show verified source, captured projection, partial or unavailable states distinctly. Missing Git objects or legacy incomplete source must not hide otherwise valid test outcomes, accounting or trace details. If current workflow bytes happen to match the recorded digest, a verified content match may be shown with its actual provenance; do not relabel them as the recorded committed source.
- [ ] Treat recorded paths, commits and Markdown as untrusted data. Bound Git/object/document work and reject traversal, unsupported object types and unsafe links. Historical viewing cannot fetch arbitrary remotes, execute linked Python, authenticate, compile active provider code or initiate inference. Render historical declarations through the existing safe read-only viewer contracts.

## Acceptance

- [ ] Verify stable hashes under enumeration changes and sensitivity to changed bytes, paths, nested resources and selected overrides. Exercise multiple repositories, missing/packaged Git provenance, staged/unstaged/untracked/ignored documents, a dirty index with HEAD-matching working bytes, unrelated dirty files, capture races, mid-run edits and changed HEAD. Verify capture and execution use the same frozen source. Prove default rejection precedes graph effects and that explicit reporting skip permits the dirty graph without any Allure output.
- [ ] Replay exact historical commits, missing/rewritten objects, forged blob/aggregate hashes, unavailable snapshots, scrubbed captures, traversal and bounded oversized data. Confirm no current-source substitution, working-tree mutation or code execution. Mutations must detect omitted document/override identity checks and commit-blob verification. Renew applicable independent, package and public-boundary gates when implemented; these requirements are future work.

## Minimum recording checkpoint

- [x] Distinguish a workflow's owning source checkout from unrelated enclosing Git repositories. Exact Git roots, consumed documents tracked in the index or HEAD, and Git-owned project/build markers at the admitted root retain committed-source verification even when package metadata claims those files. For otherwise untracked installed documents, require a unique physical distribution inventory owning every selected document and its admitted-root source proof; reject metadata/RECORD aliases and ambiguous physical owners. Preserve gitless packaged-proof behavior. Reject staged, modified, untracked and ignored source inputs even when a receipt is present.
- [x] Verify real source archive extraction, wheel builds and wheel installation beneath unrelated Git repositories. Untracked installed files retain their packaged commit identity; files positively owned by an enclosing checkout retain its committed identity and dirty-input rejection. Verify index deletion does not erase ownership established by HEAD, and that source/editable metadata cannot bypass these checks.
- [x] Independently verify committed consumed-document admission and installed receipt/Git-object proof before reporting-enabled native effects, including dirty-input and tamper mutations and explicit reporting opt-out. Exact applicable unit and relocated-artifact checks pass.
- [x] Complete external code review of the consumed-document admission and installed provenance repairs.
- [ ] Complete final qualified-data and delivery review, including renewed installed artifacts.
- [ ] Human acceptance of minimum source recording. Historical lookup/rendering and its combined acceptance above remain future work.
