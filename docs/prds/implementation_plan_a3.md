# Playwright E2E evidence and retained-browser debugging

## Checklist

- [ ] Use api_agent.runtime.managed_browser.managed_browser for E2E and local-run UI browser allocation, with the shared Stealth setup enabled before any context/page or navigation. Preserve the existing attempt isolation, resolution, headed/headless and inspection/retention requirements; do not introduce a separate browser-launch policy in these runners or provider adapters.

- [ ] Run every E2E test through Playwright against the actual UI, including the initial "Ok" test. API-only behavior checks belong in integration tests, not as substitutes for UI E2E execution. Preserve the interactive test picker, explicit Continue, and E2E human-acceptance requirements; headless browser operation does not mean unattended TUI execution.
- [ ] Capture both `response_text` and `response_html` when present, including responses containing both, and attach their original values and rendered evidence to Allure under the test/attempt identity. Capture relevant conversation rounds, not only the final response, so clarification and approval flows can be reviewed.
  - [ ] Before taking rendered-response screenshots, use the agent modal's maximize control and scroll the conversation/response content to the top. Account for independently scrollable HTML frames/containers. Wait for rendering/layout to settle before capture; the initial image must not start at the bottom and cut off the answer.
  - [ ] Capture complete text and HTML output, using full-page/element capture or additional scroll-region captures where appropriate. Verify the top and remaining content are represented; a page screenshot alone must not silently omit content inside a scrollable modal/frame. Keep separate attachments for text and HTML when both exist. Capture available failure-state evidence too.
- [ ] For any Playwright error, invoke the [shared all-tab error capture](implementation_plan_a4.md) before response capture or cleanup. Screenshot each tab's current whole viewport even if no response exists; error evidence preserves current state rather than applying the normal maximize/scroll-to-top preparation.
- [ ] Declare validated `E2E_BROWSER_RESOLUTION` as a `WIDTHxHEIGHT` string, default `1440x900`, with positive integer dimensions. Apply it to the Playwright viewport in both normal and debug runs and record it with artifacts. Make it configurable through the normal `.env`/environment/CLI precedence.
- [ ] E2E always uses Playwright against the configured running UI, including real screenshots for Allure history when `LOG_CONTENT=True`; redact credentials in captures. With content disabled, retain outcome/usage evidence without response text or screenshots. Run headlessly when `RUN_UI=False` and debug is off; `RUN_UI=True` makes the test browser visible while it runs. Declare boolean `E2E_DEBUG` (default `False`) with normal config/ENV/CLI support, but metadata must explicitly exclude this field from the startup missing-default/save-default prompt step. An unset value silently stays False; it must not itself trigger default-configuration interaction. Keep it visible in help and the configuration cleanup mode.
  - [ ] On the E2E test-selection screen, show an additional `d` Debug start action only when a non-empty strict subset of available E2E tests is selected. Positional selectors may pre-filter this subset, or the user may choose it interactively. Determine whether it is a subset against the entire discovered suite, not merely the filtered picker list, and do not enable debug for selectors that match every test.
  - [ ] Pressing `d` starts the selected tests with effective `E2E_DEBUG=True` for that invocation, after the same explicit continuation/human acceptance as normal E2E start. If debug is explicitly configured, validate the subset restriction before execution; never silently start an all-tests debug run. With debug off, `RUN_UI` determines browser visibility and browsers close normally; it does not make UI startup optional for E2E.
  - [ ] Debug always uses headed browsers and retains a separate browser for each selected test after it finishes, passed or failed, so the user can inspect its rendered state at the end. Keep browser/Playwright ownership alive beyond pytest test teardown and report completion; don't accidentally close the browser with its fixture or driver. Confirmation attempts retain attempt identity/evidence without opening an unbounded browser per attempt.
  - [ ] Keep normal Allure, usage, quota, and retry reporting in debug runs. Allow the user to close retained browsers/end the debug session explicitly; the TUI stays responsive and manages owned browser processes without auto-closing them merely when a test completes.
- [ ] Provide optional agent inspection of the same browser used by one explicitly selected debug E2E test, and by an opted-in local run. Retained-browser ownership must be implemented before attachment; use a shared inspection seam for both modes.
  - [ ] Spike attaching Playwright MCP to the owned Chromium instance through a loopback CDP endpoint, or an existing-page Playwright endpoint if CDP cannot preserve the required context. Publish the run/test/attempt and page identity so an agent can select the original page, with its current DOM, cookies and storage; do not silently create a substitute browser, context or page. The existing extension-mode MCP browser is a separate instance unless explicitly connected.
  - [ ] Enable the inspection endpoint only for opted-in development inspection, bind to loopback, and include provider-authentication browsers through the same shared inspection owner. Authentication code remains provider-owned. The launcher retains browser lifetime; attaching/disconnecting an inspection client must not dispose it. Pause test automation during inspection, preserve already-recorded results/evidence, and use the existing explicit end-debug/local-shutdown action for cleanup.
  - [ ] Verify identity and lifetime on controlled pages: observe a marker and state created by the runner through the inspection client, including after pytest completion; keep the browser alive after client disconnect, isolate concurrent runs, handle unavailable attachment actionably, and remove endpoints/processes on explicit shutdown. Human-review one selected E2E test and a local run through the same-browser attachment. MCP installation/client configuration remains developer-tool setup outside the application README.
  - [ ] Make implemented inspection discoverable through CLI help, the TUI's debug/local-run actions and attachment status, and concise README examples for one selected E2E test and a local run. Include how to identify and attach to the owned page and end inspection. Human-review these instructions, then discuss whether a minimal AGENTS.md discovery hint is needed; propose exact wording and alternatives (including omission) under its existing approval rules before making any AGENTS.md edit. Do not document commands as available before they work.
- [ ] Add deterministic coverage for resolution validation, silent debug default, strict-subset gating (including pre-filtered selectors), headed/headless selection, and browser retention/cleanup orchestration. Verify maximize/top-first and text-only/HTML-only/combined artifact capture using a controlled UI fixture before relying on live LLM E2E evidence. Live E2E checks still require user acceptance.

Implementation sources: [Playwright screenshots](https://playwright.dev/python/docs/screenshots) describes page and element capture; [Playwright browsers](https://playwright.dev/python/docs/browsers) covers browser installation and headed/headless support. Ensure the installed browser supports both normal headless and debug headed operation.

Attachment sources: [Playwright MCP configuration](https://github.com/microsoft/playwright-mcp#configuration) supports CDP and bound-browser endpoints; [Python CDP attachment](https://playwright.dev/python/docs/api/class-browsertype#browser-type-connect-over-cdp) attaches to an existing Chromium instance, with lower fidelity than the Playwright protocol. Validate actual page/context preservation in the spike rather than assuming that using Playwright in both processes makes them share a browser.

- [ ] Compute E2E browser visibility as `RUN_UI or E2E_DEBUG`; explicit `E2E_DEBUG=True` is always headed and retains browsers after the selected tests regardless of `RUN_UI`. Keep the existing subset-only debug restriction and map the shared DEBUG retention policy to E2E while preserving E2E_DEBUG compatibility; do not maintain separate browser visibility implementations. Test all visibility/retention combinations without sacrificing screenshot evidence.

It controls browser visibility without disabling mandatory E2E UI_SOURCE_DIR/UI_NX_APP; exclude it from collection-only and unrelated modes. Runner visibility/retention wiring remains above.

- [x] Prove headed provider-authentication inspection on a controlled original page through a loopback CDP endpoint, retain the browser after owner transfer, preserve it after client disconnect, and close it on explicit inspection shutdown. The integration debug worker now exposes this endpoint for the original subscription login page.
- [ ] Make agent attachment available independently of retention/debug when an operation opts into development inspection. Debug controls lifetime, not permission to attach. For integration, expose the suite's single authentication browser and allow multiple selected tests once shared backend setup is in place; distinguish multiple provider/role pages explicitly. Keep the E2E single-selected-test attachment policy until multi-test browser/attempt identities and selection are implemented.
