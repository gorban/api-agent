# Compact live diagnostics for attached agents

[Inspector](implementation_plan_b1c.md) · [Evidence contract](implementation_plan_b1c1.md) · [Diagnosis and viewer](implementation_plan_b1c2.md)

Give an agent inspecting Run local a cheap read-only connection to execution evidence without requiring root-trace payload downloads. Deliver this API-first portion of the inspector before richer historical/live presentation and final performance optimization. Existing graph/application capture prerequisites still apply.

## Connection and ownership

- [ ] With Run local DEBUG, print a labelled loopback diagnostics discovery address alongside the original browser's CDP address, after the managed server is ready. Discovery describes schema/version, process generation, features, limits, retained runs and exact next links. Reuse the inspector's server, scrubbed journal and lifecycle; no separate tracing service, persistent database or inference is needed to connect.
- [ ] Keep bounded event and detail retention in process, with independent limits and explicit expired/gap states. Share the same sanitized origin events, graph/turn/visit/attempt/call identities and accounting joins used for Allure artifacts when recording is enabled. Final settlement and live provisional summaries may differ in completeness, never in identity. `--skip-allure-reporting` does not prohibit this in-memory development inspection or create persisted Allure results.
- [ ] Apply the existing loopback, Host/origin and ephemeral authorization contract. Printed addresses contain no authentication capabilities or credentials; provide safe local client connection instructions through the approved session mechanism. Diagnostic reads cannot execute graphs, approve input, change state/configuration, authenticate providers or spend tokens. Slow/disconnected readers must not stall or cancel graph execution.

## Compact stream

- [ ] Serve one-way SSE plus bounded snapshot/cursor JSON reads. Stream graph/component/node start, completion, failure, retry and accounting-update summaries, with bounded/coalesced progress updates and heartbeats. Do not send token-by-token response text or whole state snapshots. Reconnect uses owner-assigned sequence/event IDs; process changes, evictions and missed ranges require explicit resnapshot. Define numeric event/byte/client/rate/time budgets before implementation.
- [ ] Each node summary identifies the component hierarchy and node ID/name/kind, run/conversation/turn/graph/node invocation, status and relevant loop/internal-attempt context. Show current attempt and maximum where defined, including ancestor repeatable components; unknown maxima remain unknown. Preserve the distinction between repeated visits, semantic retries, transport retries and whole-test attempts.
- [ ] Include elapsed duration from shared monotonic timing, observed token counts, estimated cost and its basis/completeness. Before subscription quota settlement, use qualified historical calibration or validated list pricing when available; never present a provisional token estimate as a measured quota charge. Missing usage/prices stay unavailable rather than zero. Later reported charges or settlement produce identified updates. Mark inclusive component totals and exclusive leaf attribution so summaries cannot double-count calls.

## Progressive detail and optional MCP

- [ ] Default discovery/turn summaries expose bounded metadata, first actionable failure and top slow/costly invocations. Drill down by stable invocation ID to attempts/calls, then selected input/output fields or bounded slices. Disclose available sizes and capture status before loading content. Apply server-enforced pagination/filter/item/byte/time limits and explicit truncation; never return an entire conversation or trace tree as a default detail response.
- [ ] Apply LOG_CONTENT and credential exclusion before the journal, queue, SSE and JSON boundaries. False reports content withheld; True allows permitted scrubbed detail only on explicit selection, with no hidden chain-of-thought or authentication state. Binary evidence uses bounded explicit references, not inline payloads. Evicted content is expired; do not silently fetch remote tracing or historical artifacts to fill it.
- [ ] Document a summary-first command-line client workflow, including a filtered, bounded SSE observation and targeted JSON reads. Continuous streams belong in a bounded client collector, not an unlimited model context. Browser, command-line and any future MCP consumer reuse the same projections. Propose AGENTS guidance under its exact-edit approval process when the feature works.
- [ ] Start with HTTP JSON/SSE. Assess a thin read-only MCP adapter only if it improves supported agent-client access; reuse the same data, pagination, privacy and budgets rather than another trace implementation. Pin and verify supported protocol/client versions at that point. MCP does not inherently reduce payload size, and adding it must not make whole-trace retrieval the default.

## Acceptance

- [ ] With a managed DEBUG browser attached, inspect deterministic multi-turn nested/parallel/loop/retry/failure examples through the printed address. Verify hierarchy, attempts/maxima, elapsed values, provisional/final costs, source generations and Allure identity parity without requiring Allure persistence or another tracing backend.
- [ ] Use large synthetic input/output payloads to prove metadata-only stream size and bounded selective reads; record client bytes needed to locate a failure or costly node without a root payload dump. Test LOG_CONTENT states, credentials across split events, missing/partial usage, unknown loop bounds, eviction, reconnect/races, slow clients, closure and repeated cleanup. No paid inference is required.
- [ ] Mutations must detect payloads leaking into summaries, omitted privacy/bounds/identity checks, dropped gap reporting and duplicated cost attribution. Independently review schema, actual HTTP/SSE lifecycle and agent usability; renew applicable exact coverage, installed-package/license and public-boundary gates before implementation acceptance.
