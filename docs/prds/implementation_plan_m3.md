# Provider contract hardening before real consumers

The version-1 exports and synthetic owners exist, but their consumer contract is provisional. Complete remaining entries before extending consumers or declaring the surface stable. The authentication-only GPT consumer already exercises the implemented subset. Keep upstream protocols outside core; use independently authored synthetic fixtures for public proofs.

## Delivered consumer foundations

- [x] Selected-provider Python manifests, explicit declaration authority and relocated packaged-resource validation; see [distribution requirements](implementation_plan_m3a.md). Actual integration preparation passes only the selected LLM and explicitly required API/access capabilities; local-operation preparation is a future consumer seam.
- [x] Shared retained DEBUG authentication/inspection, configured parallel workers and prepublication final quota capture; see [inspection ownership](implementation_plan_m3b.md). Synthetic and controlled-browser proofs remain distinct from human login acceptance.
- [x] Optional execution-only native quota preparation; see [quota-client requirements](implementation_plan_f3a.md). Read-only measurements and history do not install or sign in.

## Conformance and remaining consumers

Complete the [consumer conformance checklist](implementation_plan_m3c.md) before freezing version 1. It retains activation, cleanup, credential/revocation, installed-consumer and cross-platform requirements; the delivered subsets above do not close the whole contract.

- [ ] Add an optional provider-owned tool/catalog seam: generic names, descriptions, input schemas and result/evidence metadata. Keep API-specific query/schema types inside the API provider. ## Early phase boundary

The [included personal GPT adapter](implementation_plan_f2.md) is early work. Real demo UI/Nx apps, demo GraphQL servers and demo non-GraphQL providers are later work. Public units use synthetic fixtures; early live API/UI acceptance may use separately owned external pack providers. Those private consumers do not become public dependencies or fixtures.

## Current implementation checkpoint

Shared inference data, safe operational classifications/context, managed stream leases and independently selected access adapters are implemented. Units use two distinct synthetic transport mappings through the same consumer. Username helpers and strict in-process kind/index binding are implemented. Runtime/operation cleanup and explicit capability activation are covered by synthetic parent-ownership proofs. Human review of this concrete chunk remains pending.

Operation-specific dependency groups, installed-pack executable consumers, non-POSIX replacement/abrupt-exit guarantees and API invocation credential/revocation contracts remain open. Selected dependency descriptors now join integration and the future local-operation seam. Retained DEBUG uses the same backend as ordinary integration; neither exports raw credential endpoints. See [the conformance checklist](implementation_plan_m3c.md).

## Selected configuration and credential follow-through

- [ ] Before claiming equivalent password-manager loading guarantees on platforms without directory-handle support, implement and verify protection against intermediate-directory replacement there. Current POSIX loading uses component-wise no-follow directory handles; the direct-file fallback and simulated portability test do not establish real Windows race protection. See [the password-manager interface](../architecture/password_managers.md).
- [ ] Add browser-free scoped credential acquisition for API-key providers before the included GPT consumer. Retrieve the selected entry password only, register it with the emission boundary, own its in-memory lifetime, reject late/revoked replies, and allocate no browser for that acquisition. No separate plaintext API-key setting is needed for the included GPT adapter.
- [x] Verify the implemented bundled authentication factory defaults relative to base root/package, explicit pack/provider overrides and inert help/configuration discovery; source and narrow wheel factory/declaration checks pass.
- [x] Validate whole relocated pack manifests, schemas and selected dependency descriptors without importing factories; [M3A](implementation_plan_m3a.md) records the packaged proof. Executable installed-pack consumer acceptance remains in [M3C](implementation_plan_m3c.md).

## Authentication consumer already joined

- [x] Use the shared browser-closure guard for GPT callback waits and in-flight credential retrieval, synchronously drain owned work, preserve accepted callbacks and stop closed-browser tests promptly. Apply the same guard to future provider/UI/E2E consumers through the open debug/browser tasks above.
- [x] Keep scoped username/password/TOTP helpers and auth-only session reuse active without exporting token getters or browser objects across processes. Independent run-complete/inspection-open ownership is implemented; retained-backend DEBUG is joined; future API invocation contracts remain open.
