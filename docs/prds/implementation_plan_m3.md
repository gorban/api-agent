# Provider contract hardening before real consumers

The version-1 exports and synthetic owners exist, but their consumer contract is provisional. Complete remaining entries before extending consumers or declaring the surface stable. The authentication-only GPT consumer already exercises the implemented subset. Keep upstream protocols outside core; use independently authored synthetic fixtures for public proofs.

## Ordered checklist

- [ ] Complete operation activation and selected dependency preparation; the implemented `activation_kinds` matrix already separates runtime factories/routes from configured selections. Declaration discovery may support help/configuration, but import, dependency preparation, client startup, route activation and UI launch happen only for capabilities needed by that operation. Prove unusable unrelated selections do not block units, help, collection, LLM-only rendering, access-only checks, UI-free integration or local-run without UI. Allow separately owned callback listeners without launching a frontend.
- [x] Specify the minimum shared LLM data: messages/content, tools and calls/results, generation options, structured-output requests, available selections, completion outcomes, stream event kinds and terminal usage. Declare optional features and consistently reject unsupported requests. Keep API invocation payloads adapter-defined. Verify one unchanged renderer with two synthetic LLM adapters before freezing these schemas.
- [x] Define immutable operation context with correlation, one overall deadline spanning authentication/retries/streaming, cancellation semantics and separate bounded cleanup. Specify safe operational error kinds, execution disposition (`not_started`, `possibly_executed`, `completed`), optional retry delay and retry authority. Preserve approved safe errors; sanitize unknown failures and prohibit automatic mutation replay when execution is uncertain. At an expired deadline only a fresh native coroutine proves `not_started`; opaque or suspended awaitables are `possibly_executed`. Hidden preexisting delegates of opaque inputs remain their external owner's disposal responsibility.
- [x] Replace bare stream lifetime assumptions with a managed stream lease. Hold ownership through iteration, exhaustion or explicit awaited close. Cover early break, cancellation, iteration failure, partial output and exactly-once terminal usage; never rely on garbage collection to stop a stream. Coalesce child cancellation at read/close boundaries so awaited disposal is not interrupted by a second cancel; retain cleanup-pending ownership until retry confirms disposal.
- [ ] Propagate typed cleanup disposition through session, provider, runtime and operation owners. Keep a failed child's required clients/modules/browsers/prerequisite leases until confirmed disposal, retain a retry handle, and allow independent siblings to close. Test pending cleanup across every parent boundary. Share coalescing, cancellation shielding and retry policy without erasing distinct owner responsibilities.
- [ ] Complete live-operation credential scoping/revocation and IPC; in-process readers and helpers already support username, password and TOTP through [the helper tasks](implementation_plan_a2.md). Bind each retrieval to the allowed role/account and live operation; reject unsupported kinds and late replies after revocation.

Freeze provider/account/configuration and expose versioned, capability-protected readiness leases only; credential readers, provider tokens and browsers remain backend-local. Reject stale scopes/attempts, revoke disconnected waiters independently, and retain failed backend disposal through consumer cleanup receipts. Preserve actionable approved errors and relayed timing without provider identifiers. Shared authentication deadlines must not inherit a shorter initiating worker deadline; real multiprocess proofs cover that isolation and single setup across base/pack/provider suites. See [shared authentication ownership](../architecture/shared_authentication.md).

## Early phase boundary

The [included personal GPT adapter](implementation_plan_f2.md) is early work. Real demo UI/Nx apps, demo GraphQL servers and demo non-GraphQL providers are later work. Public units use synthetic fixtures; early live API/UI acceptance may use separately owned external pack providers. Those private consumers do not become public dependencies or fixtures.

## Current implementation checkpoint

Shared inference data, safe operational classifications/context, managed stream leases and independently selected access adapters are implemented. Units use two distinct synthetic transport mappings through the same consumer. Username helpers and strict in-process kind/index binding are implemented. Runtime/operation cleanup and explicit capability activation are covered by synthetic parent-ownership proofs. Human review of this concrete chunk remains pending.

This does not complete selected-provider dependency manifests, relocated installed packs, declaration authority, retained-backend DEBUG survival, future invocation credential/revocation contracts, complete concrete inference/API adapters or full runner/browser integration. Ordinary integration readiness IPC is implemented; no raw credential endpoint is needed for that consumer. The authentication-only GPT integration and its retained browser seam are implemented under [lazy setup](implementation_plan_f2b.md). Base/pack dependency installation still uses their project manifests; provider-specific preparation must adopt the activation matrix when those manifests are implemented. Keep the larger activation/distribution/credential checklist entries open until then.
