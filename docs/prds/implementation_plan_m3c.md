# Provider consumer conformance

[Provider hardening summary](implementation_plan_m3.md). Delivered manifest, DEBUG ownership and optional quota preparation are linked there. The remaining checklist preserves requirements for future concrete consumers.

## Ordered conformance checklist

- [ ] Complete operation activation and selected dependency preparation; the implemented `activation_kinds` matrix already separates runtime factories/routes from configured selections. Declaration discovery may support help/configuration, but import, dependency preparation, client startup, route activation and UI launch happen only for capabilities needed by that operation. Prove unusable unrelated selections do not block units, help, collection, LLM-only rendering, access-only checks, UI-free integration or local-run without UI. Allow separately owned callback listeners without launching a frontend.
- [x] Specify the minimum shared LLM data: messages/content, tools and calls/results, generation options, structured-output requests, available selections, completion outcomes, stream event kinds and terminal usage. Declare optional features and consistently reject unsupported requests. Keep API invocation payloads adapter-defined. Verify one unchanged renderer with two synthetic LLM adapters before freezing these schemas.
- [x] Define immutable operation context with correlation, one overall deadline spanning authentication/retries/streaming, cancellation semantics and separate bounded cleanup. Specify safe operational error kinds, execution disposition (`not_started`, `possibly_executed`, `completed`), optional retry delay and retry authority. Preserve approved safe errors; sanitize unknown failures and prohibit automatic mutation replay when execution is uncertain. At an expired deadline only a fresh native coroutine proves `not_started`; opaque or suspended awaitables are `possibly_executed`. Hidden preexisting delegates of opaque inputs remain their external owner's disposal responsibility.
- [x] Replace bare stream lifetime assumptions with a managed stream lease. Hold ownership through iteration, exhaustion or explicit awaited close. Cover early break, cancellation, iteration failure, partial output and exactly-once terminal usage; never rely on garbage collection to stop a stream. Coalesce child cancellation at read/close boundaries so awaited disposal is not interrupted by a second cancel; retain cleanup-pending ownership until retry confirms disposal.
- [ ] Propagate typed cleanup disposition through session, provider, runtime and operation owners. Keep a failed child's required clients/modules/browsers/prerequisite leases until confirmed disposal, retain a retry handle, and allow independent siblings to close. Test pending cleanup across every parent boundary. Share coalescing, cancellation shielding and retry policy without erasing distinct owner responsibilities.
- [ ] Complete live-operation credential scoping/revocation and IPC; in-process readers and helpers already support username, password and TOTP through [the helper tasks](implementation_plan_a2.md). Bind each retrieval to the allowed role/account and live operation; reject unsupported kinds and late replies after revocation.
  - [x] Join ordinary integration setup to one backend-owned registry and creating loop across repository suites and parallel workers. Freeze provider/account/configuration and expose versioned, capability-protected readiness leases only; credential readers, provider tokens and browsers remain backend-local. Reject stale scopes/attempts, revoke disconnected waiters independently, and retain failed backend disposal through consumer cleanup receipts. Preserve actionable approved errors and relayed timing without provider identifiers. Shared authentication deadlines must not inherit a shorter initiating worker deadline; real multiprocess proofs cover that isolation and single setup across base/pack/provider suites. See [shared authentication ownership](../architecture/shared_authentication.md).
- [ ] Specify debug run-complete versus inspection-open states, worker/driver survival, cleanup acknowledgement/retry and unexpected worker exit. Version credential IPC with operation/worker/attempt, allowed role/account, deadline and revocation; do not transfer browser objects or opaque token getters between processes.
  - [x] Implement the integration run-complete/inspection-open protocol in `testing/integration.py`, `testing/inspection.py` and `testing/provider_setup.py`. Finish reports before retained-window disposal; transfer cleanup ownership to terminal/TUI consumers and acknowledge/retry explicit shutdown. Preserve reader/process-group ownership on incomplete cleanup. POSIX parent-liveness EOF stops only the worker's confirmed own process group after abrupt launcher exit; other platforms remain below.
  - [x] Preserve cleanup receipts across terminal output errors, launcher exceptions and unexpected TUI shutdown. Drain cancelled executor work before acknowledging teardown, adopt its late result/error owners, and preserve cancellation status after cleanup. Bind callbacks and retries to the original operation, inspection group and reporting owner; stale receipts cannot close or reset a later operation.
  - [ ] Complete platform-specific abrupt launcher recovery where POSIX process groups/liveness pipes are unavailable.
  - [x] Establish shared readiness and revocable scoped credentials in `providers/shared_setup.py`. Dispose readers/authentication/provider resources in dependency order and retain failed children for retry. This began as worker-local ownership; ordinary integration now adopts it inside the shared backend above. Retained DEBUG is joined in [M3B](implementation_plan_m3b.md); future API invocation contracts remain open.
  - [x] Move retained DEBUG authentication/inspection to the shared backend and enable configured parallel execution after controlled multiprocess/browser ownership proof. Verify stopped-loop recovery and owned launcher death on Linux; preserve retryable cleanup and final quota before publication. Other-platform abrupt-exit guarantees remain unchecked below. Future API consumers need explicit invocation/revocation contracts rather than raw tokens.
  - [x] Freeze the selected provider/account and credential descriptor snapshot while its implementation loads. Reject changes before authentication, dispose the original provider and retain failed disposal for retry. Require exact integer inspection protocol versions; malformed or duplicate commands preserve browser ownership until a valid request.
  - [ ] When completing worker/inspection cleanup, verify orphaned worker/driver recovery against registered operation identities and confirmed ownership. Do not stop arbitrary host processes or containers by name alone. Retained debug windows must remain distinguishable from abandoned workers; audit unexpected launcher exit and synchronous termination acknowledgement.
  - [ ] Reuse the shared `wait_browser_result` browser-closure guard for pending provider browser waits across integration/E2E/local-run and for the separate E2E UI browser when wiring its runner. The caller owns cancellation/draining of underlying work. Closing before completion must finalize an unsuccessful outcome promptly, release owned listeners/tasks and publish available failure evidence; accepted authentication callbacks remain successful. Verify normal and debug retention paths, unrelated-tab closure and browser disconnection. A closed browser must not leave a test RUNNING until its operation timeout.
- [x] Define selected Python distribution manifests, explicit declaration authority and whole relocated pack validation in [M3A](implementation_plan_m3a.md). Source-tree file factories remain supported.
- [x] Prove installed file-provider discovery, loading, invocation and disposal through [installed execution conformance](implementation_plan_m3d.md). This verifies the existing loader consumer, not the Django application or operation runner.
- [ ] Verify broader installed application/runner consumers as their operation wiring is completed; archive inspection and loader conformance alone do not complete that acceptance.
- [ ] Complete operation-specific dependency groups beyond the implemented descriptor joins.
- [x] Document and enforce declaration authority in [M3A](implementation_plan_m3a.md): explicit override, inherited omitted constraints, permitted defaults/presentation and rejection of incompatible or unauthorized weakening.
- [x] Separate non-inference access adapters from the selected inference provider. Specify independent selection, scoped authentication/routes, optional discovery/usage capabilities and no inference capability. API principal validation must not require an unrelated LLM service identity.
- [ ] Join consumer-level conformance for activation, two LLM adapters, pending parent cleanup, early stream close, safe errors/deadlines, worker inspection and credential isolation. Human-review the concrete contract before declaring its supported surface stable. Prior foundation coverage does not establish these new proofs.
