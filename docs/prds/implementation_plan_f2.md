## Configuration acceptance matrix

| GPT_AUTH_MODE | GPT_API_MODE | Configuration rule |
| --- | --- | --- |
| subscription | responses | Valid with eligible integration/account; API-key vault role is inactive and unused |
| subscription | completions | Invalid; fail before OAuth/client/request activity |
| api_key | responses | Valid with a valid selected vault login whose password is a nonempty API key, and supporting endpoint/selection |
| api_key | completions | Valid with a valid selected vault login whose password is a nonempty API key, and supporting endpoint/selection |

All GPT settings are provider-contributed and use normal effective-pack defaults and .env/environment/CLI precedence. The matrix specifies intended support. Subscription/responses authentication is implemented, and subscription/completions rejects before side effects. Both API-key modes remain configuration-valid but operationally unimplemented; their setup raises the explicit prerequisite boundary and dependent integrations skip. Discovery and inference remain unimplemented for every mode.
