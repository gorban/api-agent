# Bedrock workflow integration and acceptance

[Bedrock requirements](implementation_plan_f4.md) · [Transport and costs](implementation_plan_f4c.md)

The controlled [Mantle matrix](implementation_plan_f4d.md) now has focused parser/LangGraph, six-mode, tool/stream and ownership verification. Broader structured-output, concrete login and finalized accounting requirements below remain open. Focused results do not establish live or production acceptance.

## Working integration

- [ ] Contribute an ordinary versioned factory, typed configuration and installable optional dependencies using existing provider discovery/setup contracts. Missing optional dependencies give actionable setup guidance; unselected providers, help, configuration and collection must work without AWS installation/login. Document provider selection, profile/region/model setup, required permissions and credential-manager item fields with synthetic examples.
- [ ] Parse a synthetic flow.md.html through the existing executable declaration parser, compile it through the current LangGraph builder and run through the normal application/test Runtime with the selected Bedrock provider. Exercise both application and integration-test contexts; do not replace this with a standalone SDK or separately hardcoded graph. Keep compatibility with existing tool declarations; a future tool-instance grammar is not prerequisite evidence.
- [ ] Prove completion, terminal stream/result reconstruction, a supported tool-call/result turn and supported structured output through that graph boundary. Preserve model/version, regional or inference-profile route, options, tool-call IDs and usage. Unsupported model capabilities fail before requests where determinable. Establish the initial supported matrix rather than implying all Bedrock models share capabilities.
- [ ] Qualify both Mantle Chat Completions and Responses through the ordinary LangGraph/provider boundary under the [Mantle-only contract](implementation_plan_f4d.md). Do not retain Converse/ConverseStream or model-specific InvokeModel as active target transports. Earlier controlled SDK results remain historical evidence rather than Mantle acceptance.
- [ ] Own synchronous SDK/helper work explicitly when used under async APIs. Apply the shared timeout/progress boundary, bound SDK network timeouts/retries, terminate streams and dispose clients/owners after success, failure, cancellation and partial setup. Cancelling an await alone is insufficient proof that blocking SDK work stopped; test remaining worker ownership and no subsequent calls from disposed sessions.

## Controlled verification

- [ ] Do not emit actionable streamed tool calls until the complete stream and originating request's declared tool names, argument schemas and unique call IDs validate. Reject malformed/truncated streams without tool-call or completed-result publication. Require the selected API's reported input/output/total usage before accepting completion; preserve separate cache normalization. Classify HTTP/SSE failures without forwarding raw diagnostics. Transport shutdown must drain admitted HTTP work and credential-worker launches/owners before acknowledging closure. Attempt independent cleanup owners even when one fails, retaining outstanding ownership for a later cleanup retry.
- [ ] Write deterministic requirement tests red-to-green where practical before implementing behavior. Test credentials/index isolation, missing-factor attended recovery, NO_STD_IN, expiry/refresh, concurrent setup, request mapping, fragmented/error streams, tool/schema rejection, timeout clipping, partial cleanup and credential-safe errors. Offline tests use controlled SDK/helper doubles or loopback fixtures and cannot access real credential files, metadata services or AWS endpoints.
- [ ] Measure exact 100% line and branch coverage on all wholly new production Python files during initial development. Run focused affected tests and existing-behavior regressions while iterating; report measured new files and any unmeasured/untested scope. Do not claim complete repository coverage from focused results. Use meaningful causal mutations where an unrelated check could mask the intended rejection.
- [ ] Prove regional catalog/admission separately from authentication and inference. Missing model access, unavailable regional routes, throttling, access denial, retries and partial usage remain explicit. Authentication success or a catalog entry is not proof of invocation access.
- [ ] Qualify distinct synthetic Bedrock rates/usage and same-model cross-provider isolation, failed/blocked/retried charges and ancillary-cost uncertainty through finalized Allure, SQLite rebuild and picker/completed costs. Preserve original evidence and generic versioned contracts; never fall back to GPT rates or fabricate exact AWS spend.
- [ ] Verify source, installed and relocated provider resources, declarations and optional dependency manifests. Preserve licenses/notices; perform independent adversarial review and public-boundary/provenance checks. Record unsupported cases and unresolved findings.

## Human/live and production gates

- [ ] Review non-secret profile/region/model/role, permissions, MFA and password-manager setup before first live authentication. Wait for explicit readiness; no credentials are required to complete offline work. Prove each advertised attended/unattended acquisition path separately and record unavailable federation prerequisites honestly.
- [ ] Authorize live inference separately with a USD ceiling, specific model/route/region, allowed test selection, request/token/retry limits and conservative pre-request enforcement. Authentication readiness does not authorize spending. Run only the approved matrix; distinguish estimated/token-derived costs from qualified reported totals and delayed billing.
- [ ] Present the integrated result and known limits for human/external review before production adoption. At main integration run all applicable unit tests and require exact 100% line/branch coverage under repository rules, plus affected integration/package/boundary checks. Focused development results do not waive this gate or constitute acceptance of later consumers.

Use independently authored synthetic workflows and fixtures.
