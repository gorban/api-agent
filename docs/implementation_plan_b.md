# Declarative executable descriptions

## Checklist

- [ ] Define declarative formats for configuration and LangGraph flow, and identify other behavior that should use executable descriptions during planning.
  - [ ] Let implementors choose and evolve the concrete configuration/pack declaration formats as they implement the consuming tasks. Make schemas versioned and runtime-validated, with examples and generated documentation for human review. Implement the fields needed now; include likely later fields together when their data/contracts are already known and convenient, without making inactive future features required. Review the resulting declarations through the parent implementation checkpoints rather than requiring a complete schema design before implementation.
  - [ ] Require a type for each configuration value and describe whether it is optional and whether it has a default. Use these declarations for the TUI/application type checks, missing-value handling, environment/CLI mapping, and generated configuration documentation.
- [ ] Compose shared configuration declarations with only the selected resource pack's extensions; do not require or prompt for another pack's configuration. Declare test-owner identity/root and per-mode test paths in the pack description. Pack unit paths are optional; unit mode always includes the base api-agent unit suite. Integration/E2E suites are selected by the pack.
  - [x] Support a pack-launcher-only typed directory setting `API_AGENT_DIR` / `--api-agent-dir` (also `--api_agent_dir`) defaulting to `../api-agent` relative to that pack's root. It locates the base runtime and is not a required setting for launching api-agent directly.
  - [x] Resolve this bootstrap setting before loading the base runtime, applying pack-root `.env` < environment < CLI precedence and anchoring relative values to the pack root. Keep bootstrap resolution noninteractive; validate the resolved base entry point and report how to override an invalid path. Share the bootstrap logic between pack launchers without copying the full TUI/config implementation. After loading the base, retain the value/source for normal declarative configuration handling.
- [x] Resolve hierarchical defaults from shared declarations followed by selected-pack default overrides, then apply explicit values in base-root `.env` < selected pack-root `.env` < environment < CLI order. Read both files; a missing key in the pack file retains the base-file value. Pack defaults are still defaults, not explicit user input; validate them against the shared field type and retain source provenance for generated docs and TUI display.
  - [ ] Resolve controlling options first, then determine which conditional settings apply to the selected mode/features. Prompt or aggregate errors only for active required settings; inactive API/database/UI/Langfuse fields must not block startup. Re-evaluate applicability when a controlling choice changes.
  - [x] Include `RUN_UI`, `UI_SOURCE_DIR`, and `UI_NX_APP`. Require UI configuration for E2E execution and local-run with `RUN_UI=True`, using selected resource-pack defaults where declared. Unit and integration tests do not require UI configuration regardless of `RUN_UI`. Declare the path anchor for each directory default/override explicitly so launcher-root UI paths and pack-root base/API paths do not depend on the current working directory. See [infrastructure/UI configuration](implementation_plan_h.md).
- [ ] Parse these descriptions programmatically at runtime to configure the application and construct the executable LangGraph flow.
- [ ] Derive configuration documentation and flow diagrams from the same descriptions, avoiding separately maintained representations that can drift out of sync.

- [ ] Define a restricted Markdown `layout.md` as the executable source of truth for graph structure, data bindings, retry groups, and prompt composition, using genuine declaration-relative links for local prompts and explicit `<resource_pack>` links for runtime-selected pack prompts. See [strict Markdown Layout plan](implementation_plan_b1.md); show the implementor's concrete grammar/declarations at human review and refine them as needed.
  - [ ] Resolve named Python node and condition functions through a function registry and construct/compile LangGraph nodes and unconditional or conditional edges at runtime. Report unknown function references and invalid layouts before execution.
  - [ ] Declare input/output reference IDs. Bind an input to a matching output from an earlier executed node; where no previous output supplies it, require the runner to supply it (for example conversation history, user prompt, or UI context). Report missing required inputs. Preserve the distinction between tool results and user-provided content.
  - [ ] Declare sub-groupings with their own bounded loop behavior, condition function references, and attempt budgets. Support a planner/plan_verifier group with an initial attempt and one retry, and a later graphql_executor/graphql_verifier group with its own independent attempts. Define success and exhausted-attempt exits; group retries must not consume another group's budget. These verification loops are distinct from exception retry policies.
  - [ ] Include an ordered prompt section containing file links. Each entry applies unconditionally or has an optional named condition function deciding whether it applies. Apply included prompts in declaration order.
  - [ ] Support the special path variable `<resource_pack>` in prompt paths, resolving it to the selected resource pack directory. Use whatever is selected by `--resource-pack-dir`, or an included demo resource pack by default for standalone api-agent. Report unresolved variables and missing applicable prompt files.
- [ ] Generate the human-readable flow documentation/diagram from the same Layout loaded by the runner. The Layout describes orchestration; named function implementations remain Python code.
- [ ] Add targeted integration coverage for conditional routing, output-to-input and runner-provided bindings, independent group retries/exhaustion, ordered conditional prompts, and switching between demo and selected resource packs. Establish [Allure reporting](implementation_plan_d.md) before writing these tests.

Implementation reference: [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api) provides programmatic nodes, conditional edges, graph state, and loops. The Layout format and loader are project features to build on that API.

- [ ] Declare `TUI_MODE` as required when `NO_STD_IN=True` unless `HELP=True`, and preserve whether its test-mode value came explicitly from `.env`/environment/CLI for unit-only picker bypass and positional selectors; integration/E2E execution always stops at the filtered interactive test picker. Make `E2E_RERUNS` applicable only to E2E; unit/integration have no retries.

- [ ] Describe the conditional local-run `RUN_LOG_SOURCE` default in executable configuration: `all` when `NO_STD_IN=True`, otherwise `agent`, subject to pack defaults and explicit value precedence. Validate named sources against active service declarations; menu numbers are not configuration values. Use this default through both TUI and unattended launch paths.

- [ ] Declare boolean `HELP` and `COLLECT_ONLY`, both defaulting to `False`, including the special `-h` alias for `HELP=True`. Resolve the help short-circuit before execution configuration checks, and make collection-only validate only active collection requirements. Preserve explicit mode provenance so collect-only can bypass all interactivity when a test mode is supplied through `.env`/environment/CLI.

- [x] Reject `NO_STD_IN=True` for integration/E2E execution as an incompatible configuration before startup. Keep `HELP` and configured-test-mode `COLLECT_ONLY` as nonexecuting, noninteractive shortcuts; collection does not require execution acceptance.

- [ ] Declare typed `UNATTENDED_AUTH` role-to-entry-array credential sources (compact JSON object) for provider-declared authentication. Additional credential roles and their configuration fields belong to provider or resource-pack declarations/adapters; apply only selected profiles when validating setup. Derive both configuration cleanup and unattended-auth setup fields from these executable declarations. See [authentication setup](implementation_plan_a2.md).

- [ ] Declare `E2E_BROWSER_RESOLUTION` (validated `WIDTHxHEIGHT`, default `1440x900`) and boolean `E2E_DEBUG=False`. Add declarative field presentation metadata to exempt the debug default from startup default-configuration prompts without removing its ENV/CLI/help/cleanup support. Validate debug's strict-subset requirement at E2E start. See [Playwright E2E plan](implementation_plan_a3.md).

- [ ] Declare `AUTH_BROWSER_DEBUG=False` for explicit headed/retained authentication-browser debugging, distinct from subset-only `E2E_DEBUG`. Allow packs to declare an authenticated-UI launcher handler while keeping their application-specific login logic outside api-agent.

- [ ] Declare optional zero-based `UNATTENDED_USER_INDEX` shared by credential arrays for the roles needed by the operation with no default selection for multiple entries. Exclude this field from automatic default acknowledgement/persistence, and keep interactive choices session-only. Resolve zero/one/many entries through the [authentication selection rules](implementation_plan_a2.md), prompting only for roles the operation needs and failing ambiguity under `NO_STD_IN`.

- [ ] After the "Ok" milestone, declare boolean `LOG_CONTENT=False` with explicit-value provenance: a declaration/pack default must not grant content-logging permission. Only the effective explicit `True` enables the shared [logging/trace content gate](implementation_plan_j.md); omitted/default/False cases require thorough scrubbing tests.

- [ ] Keep selection of needed credential roles synchronized through `UNATTENDED_USER_INDEX` only. Preserve paired array ordering; never independently pick a secondary index. Zero-entry arrays retain attended fallback; validate a selected shared index against every nonempty array consumed by the operation, including single-entry arrays, and fail invalid pairings rather than silently using another account. Interactive selection chooses one session-only index for the needed arrays.

- [x] Support explicit typed shared-field replacement via `override = true` in pack `cfg/config.toml`, preserving the shared type and rejecting accidental duplicate fields. Support `applies_when.any` alternatives for E2E UI requirements versus optional local UI. `UI_NX_APP` and `UI_SOURCE_DIR` apply to E2E regardless of `RUN_UI`, to local run only when `RUN_UI=True`, and never to integration tests; collect-only starts no UI. Resource packs may override `UI_NX_APP` through their config declarations.

- [ ] Selected LLM providers and resource packs may declare optional `UNATTENDED_USER_INDEX` when they offer indexed credential selection, including a single LLM role with multiple accounts. Shared/demo config does not hardcode it; shared help lists it only when contributed to the active schema. Generic account selection consumes the field when present and validates the selected index across the nonempty role arrays needed by the operation. Keep session-only interactive choices and fail noninteractive ambiguity. Private provider adapters perform authenticated-identity validation.
