# Unattended provider sessions and operation usage

## Checklist

- [ ] Share an owned LLM authentication session across the selected unattended runtime. Initialize it lazily when an authenticated provider operation needs it. Unit/help/collection/configuration operations do not authenticate or read quota. Preserve human configuration review and integration/E2E acceptance.
- [ ] Give the selected LLM provider an unattended user index, its dedicated headless browser and an LLM-user credential callback. Its authentication hook returns a fresh opaque token getter and asynchronous disposal. The provider owns protocol state, refresh and any private persistence; public core does not serialize or interpret tokens.
- [ ] Keep provider authentication isolated from resource-pack UI authentication. Each E2E UI session authenticates through the resource pack before the test receives that same session. The resource pack receives tui_mode, the browser, the optional unattended index and role-bound credential callbacks.
- [ ] Let provider implementations decide whether and how to reuse persisted authentication. Contributed configuration owns cache policy. Private state must remain outside source control, diagnostics, traces and test artifacts; test reuse, isolation, expiration and cleanup within the provider.
- [ ] Capture optional starting and final quota snapshots through provider capabilities without invoking inference. Retain token counts, optional quota percentage used and quota reset datetime in UTC. Report missing, reset-spanning or otherwise invalid snapshots explicitly.
- [ ] On completion, failure or cancellation, drain workload activity, try the final snapshot, freeze one operation summary, and dispose provider authentication/refresh work before closing clients. A force-killed process cannot promise a final snapshot. DEBUG retains browsers, including the headless LLM browser, under supervised lifetime management.
- [ ] Count initial conversation turns, clarification answers and mutation approvals once at the invocation boundary. Internal nodes, retries, refresh and quota reads do not count as user prompts. Bracket the selected parallel suite once and disclose possible unrelated account usage.
- [ ] Obtain cost estimates from the provider using recorded token counts and optional quota snapshots. Core does not equate percentage points with currency. Divide a valid estimate by a nonzero prompt count; otherwise report per-prompt cost as unavailable. Measured zero remains distinct from unavailable data.
- [ ] Persist the same frozen usage summary in integration/E2E reports and show it in TUI/stdout. Local-run may show its summary without creating a test report.
- [ ] Verify lazy initialization, fresh token retrieval, runtime disposal, browser retention, credential-index isolation, concurrent requests, optional quota data, provider cost estimation and identical frozen summaries using synthetic providers. Live provider verification remains separate.
