The explicit shared test override settings are LLM_REASONING_TEST_MODEL,
LLM_REASONING_TEST_LOW_EFFORT, LLM_REASONING_TEST_HIGH_EFFORT,
LLM_REASONING_TEST_TOKEN_REPORTING, LLM_REASONING_TEST_MAX_OUTPUT_TOKENS,
LLM_WORKFLOW_TEST_MODEL, LLM_STUDIO_TEST_DEFAULT_MODEL,
LLM_STUDIO_TEST_SELECTED_MODEL, LLM_STUDIO_TEST_DEFAULT_EFFORT and
LLM_STUDIO_TEST_SELECTED_EFFORT. Review configuration describes each setting.
An unset route-specific selection is an explicit unmet qualification prerequisite,
not permission to use a hardcoded GPT model. Configured IDs must pass
LLM_ALLOWED_MODELS and actual catalog/capability checks before inference.

GPT-OSS supports low, medium and high effort through both Mantle APIs, using
the API's native request shape. Only Responses supplied explicit reasoning-token
counts in qualification. Acceptance of a request parameter, observable counters
and a measured behavioral contrast are separate claims. The selected OSS120B
Responses low/medium profile passed one complete six-call comparison at 16,000
output tokens: all replies were nonempty and below cap, with signed reasoning
increases 1,162, 1,112 and 400 tokens across three pairs. The puzzle, signed threshold
and validity guards were unchanged. This is a bounded smoke qualification, not
a claim of stable stochastic ratios or launcher human acceptance. Native
reasoning text remains suppressed. GLM's binary thinking control is not
advertised as categorical effort support.

Earlier 4,096-token low/high and low/medium batches failed through unavailable,
empty or cap-reaching replies; partial pairs did not qualify. The first OSS120B
low/medium 16,000-token batch also failed: one low reply had no visible message
or text in the maintained SDK object before product decoding. It returned all
six calls within 22 seconds, without a local timeout. The next unchanged complete
batch passed, with calls taking 6–18 seconds. Every failed batch is retained;
there were no request retries or replacement observations within a batch.
Another paid attempt requires renewed approval after this completed iteration.

The 16000-token low/high retry completed all three low replies with visible
answers below cap. Two high calls hit SDK timeouts at approximately 30 seconds;
the third application call failed at its 120-second deadline. All six admissions
were used without retries, and no high reply completed. Increasing the output
allowance alone did not resolve these deadline failures. The inference deadline now defaults to 900 seconds; the reasoning-test and
setup-session request deadlines default to 960 seconds. Explicit shorter
overrides remain effective, and parent deadlines can shorten each budget. These
defaults preserve shorter parents; the later OSS120B smoke pass is recorded above.

GLM 5 Completions is qualified for bounded strict JSON schema requests. Positive,
contradictory-prompt and invalid-schema probes complement controlled transport
tests. GPT-OSS structured requests are not advertised: a Chat probe did not obey
the schema, and a Responses probe timed out. Unsupported requests fail before
authentication or inference; received output still undergoes local validation.

Model discovery is not an entitlement check. In the tested account, GPT-OSS and
GLM requests worked; newer proprietary OpenAI models returned 401 and the newest
Claude variants returned by that catalog returned 403. These results do not
establish restrictions for another account. Claude discovery does not enable a
Messages transport in this provider.

Workflow bounds bind the exact model, region, API, authentication configuration,
adapter source, runtime/dependency versions, graph inputs and sampling source
hashes. A different fingerprint requires a fresh explicitly approved calibration.
Existing GPT measurements are not reused for Bedrock. The earlier four-pass
GLM 5 Completions pilot passed 20 graphs and 35 calls. Independent receipt,
fingerprint and exact statistics review qualified a 26-run minimum plus four
margin, giving a 30-run cap. Earlier failed runs remain retained; no successful
prefix replaced a failed pilot. The ordinary two-pass default is unchanged.

The recorded launcher runs passed all 14 Responses cases and the one Completions
workflow case, with Allure publication successful for both. See the
[ordinary integration profiles](README.md#ordinary-integration-profiles)
for exact settings and selectors. This qualifies those settings, with human
